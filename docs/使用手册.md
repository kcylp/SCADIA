# SCADIA 使用手册

适用：2026-10-15 源码基线及本轮八场景统一分析修订。先阅读[产品说明书](产品说明书.md)中的能力边界。本文描述可用操作和预期结果；真实相机、模型、现场标定和业务数据必须另外验收。

## 1. 开始使用

1. 在已部署工作站运行根目录 `启动 SCADIA.cmd`，或按部署维护手册运行 PowerShell 启动器。
2. 等待启动器显示主服务地址，打开 `http://127.0.0.1:1881`。部署修改过端口时使用站点地址。
3. 使用工程管理员分配的账号登录。手册不包含现场密码、令牌和相机连接地址。
4. 检查时间、数据更新时间、设备在线状态；画面出现不等于检测或录像服务正常。
5. 进入八场景画面，分别检查可见光和红外源；记录源离线、标定未应用、证据不足等状态。

登录失效时，先返回主界面登录，再刷新分析证据。不要把令牌放入 URL，也不要分享带相机凭据的配置文件。安全模式下八场景全局状态、帧、事件和历史图片目前限管理员查看；普通账号收到 403 应联系管理员，不应通过直接图片目录绕过。

## 2. 主要入口

| 路径 | 用途 | 使用要点 |
|---|---|---|
| `/home` | 当前工程主界面 | 实际首页由工程视图配置决定 |
| `/scenes` | 八场景检测画面、状态和门口标定 | V1–V7 共享可见光；T1 独立红外 |
| `/video` | 同一八场景组件入口 | 实际画面以当前部署为准 |
| `/people` | V1 门口进入账本 | 不是实时在室人数 |
| `/scene-records?scene=V3` | 指定场景完整事件列表 | 场景、日期筛选、30 条分页、历史抓拍与 ACK |
| `/ai-analysis` | 统一 AI 分析 | 先选模块与明确目标，再读取证据 |
| `/mes`、`/ems` | 生产 / 能源看板 | 当前含演示数据；不可用于现场决策 |
| `/device` | 设备配置 | 编辑前备份工程，注意连接参数与权限 |
| `/alarms` | 平台报警 | 检查实际报警身份和版本后确认 |

某些入口会由导航菜单或项目 HMI 内链接打开。菜单名称受工程配置影响；路由打不开时先看 HTTP 状态和登录，不要根据空白页面推断设备没有异常。

## 3. 看懂八场景卡片

每张卡片需同时关注场景编号、源、帧更新时间、规则状态和 VLM 结果。离线卡片可能仍有最后一帧，必须参考更新时间。共享可见光画面上的多个候选不是多个独立相机事件。

- V1：只统计指定门口、向内的稳定过线。未确认门口方向线时不生成进入事件。
- V2：跌倒姿态候选需要结合连续画面与人工核实。
- V3：手口动作可能来自喝水、打电话、摸脸，不能直接认定抽烟。
- V4：安全帽检测依赖实际模型和头部可见性。
- V5：聚集按配置人数阈值与持续时间触发；人数变化与跟踪断点影响候选。
- V6：禁区、滞留和方向事件依赖各自区域。室内坐着的人不应被算作 V1 进入。
- V7：烟火、通道、画质有不同证据需求；通道区域仍需现场标定，画质故障不证明火灾。
- T1：只有独立红外画面的相对热点信息，不能读作真实体温。

“复核完成”是任务状态；同一行的“支持 / 不支持 / 证据不足”和限制项才说明复核判断。巡视用于观察当前场景，没有 eventId，不写入事件次数。

## 4. 门口位置与进入方向标定

### 4.1 已知口径及未完成状态

以实际门口为进入边界；**过门后朝镜头走或朝远处玻璃门走都算进入**。不能用统一的画面左右方向代表两条路径。工位和室内走动不计数。本轮尚未取得能够可靠对应实际门框的坐标；门位置、方向线实际保存和正反通行验收均未完成。默认提示“门口方向线未确认，不生成进入记录”在这种状态下是预期行为。

### 4.2 标定前准备

由能够看见实际门口的管理员执行。确认摄像头固定、未镜像、分辨率与画面比例正确，门框及两侧稳定空间可见。裁剪、移动或镜像改变后，旧坐标需要复核。

在 `/scenes` 的门口标定区域执行：

1. 刷新并加载当前版本；保留该版本以防覆盖他人修改。
2. 选择“门区”，依次点击门口通行区域边界点。区域应覆盖门外、门槛和进入后的短暂稳定区域，避免包含室内工位。至少三个有效点，不自交、不重复、不退化。
3. 选择“方向线”，点击门槛线的两个端点。线段必须位于门区内，两侧都留出稳定空间。线段应覆盖实际门槛的有效通行范围，让进入后朝镜头和远处玻璃门两种去向都先穿过门槛。
4. 选择“室内侧”，点击门槛内侧有效点。这个点决定哪一侧是进入后的稳定侧，不能落在线上或门区之外。
5. 查看门区、方向线和室内侧叠加，核对外→内方向及两种去向。勾选“已确认门口位置、室内侧与进入方向”。
6. 保存。只有服务器回读成功才算配置已保存；收到版本冲突时先重新加载，不盲目反复保存。
7. 等待检测状态显示 `appliedCalibrationVersion` 与保存版本一致且无 `calibrationError`。仅保存文件成功，不代表 worker 已应用。
8. 做下节的正反通行。所有步骤完成前，不能在验收单写“门口计数已完成”。

清除标定或禁用后应停止新进入事件。恢复旧文件时也要重新核对版本和现场画面。示例坐标仅用于自动化测试，不能复制为现场坐标。

### 4.3 系统如何判断“进来”

系统观察同一跟踪 ID 的脚点。脚点先在门区门外侧连续稳定出现，运动轨迹跨越有限门槛线，再在室内侧连续稳定出现，才产生一次进入。边界抖动有余量和稳定帧要求；断流、长间断、退出区域会打断连续证据。同一人离开后重新在外侧稳定出现再进入，可以产生新次数。

以下不计入：一直在室内坐着；室内绕行；从室内向门外离开；只接近门槛又折返；绕过线段端点；证据丢失期间突然出现在内侧。单帧 VLM 描述不能补足这一时序过程。

### 4.4 现场验收表

记录操作者、时间、相机 ID、标定版本、真实人工次数、系统次数和事件 ID：

| 动作 | 期望 |
|---|---|
| 完整过门后朝镜头走一次 | 新增 1 条 V1，历史抓拍与此人此时相符 |
| 完整过门后朝远处玻璃门走一次 | 同样新增 1 条 V1 |
| 从室内向门外完整离开 | 不增加进入次数 |
| 门外经过、未跨门槛 | 不增加 |
| 室内工位起身、室内横移 | 不增加 |
| 门槛抖动、折返 | 不重复计数 |
| 两人相邻进入 | 能区分轨迹；误合并须记录失败样本 |
| 断流后恢复 | 不用断点前轨迹补造一次过门 |
| 重启 | 旧事件仍可查，不重复入账 |

现场验收失败时保留对应抓拍、轨迹、时间和版本，修正规则后重新测试。不要清除失败记录来只展示成功样本。

## 5. 查询八场景事件与历史证据

打开 `/scene-records`，选择八场景综合、V1–V7 或 T1，可按视频源、镜头、事件子类型、复核状态、结论和人工知晓筛选；设置开始/结束日期后查询。日期按浏览器本地日界线转换为时间戳；运行统计显示站点时区，跨时区客户端要核对筛选。无日期时查询当前可用全部历史，默认每页 30 条。

每条记录检查：场景编号 → 相机 → 发生时间 → 候选类型 / 轨迹 → 复核判断 → 标定版本 → 人工确认。源或场景与现场不符时先排查绑定，不能移到另一场景凑记录。

点击图片打开的是该事件保存的历史抓拍。图片缺失会显示不可用；不会替换为当前视频。系统重启、当前相机离线或更换相机后，旧事件仍应保留原相机身份。旧格式数据没有独立 source 字段时，统一分析标记为旧场景映射来源，不代表来源已经验真。

“今日 / 累计”以清零截点和站点日历计算，“筛选结果”是当前时间范围的历史总数。清零后累计可以为零而仍能查到旧事件，这是预期。无记录也可能是检测没启动、未标定、证据入库失败或筛选错误，不能直接断言无人进入或没有风险。

## 6. 统一 AI 分析

1. 从主界面打开“统一 AI 分析”或 `/ai-analysis`。弹窗和独立窗口仍需有效会话。
2. 视频分析选择“视频”模块，再选择八场景综合、V1–V7/T1，或从账本打开单事件。其他模块可选择其明确分析目标。
3. 选择过去 1、6 或 24 小时；点击“刷新证据”。先核对目标与证据摘要，再填写问题。
4. 视频部分会展示本场景最近 30 条事件、当前状态、独立巡视结果、复核状态和历史证据按钮。完整历史用“完整场景记录”链接。
5. 可以提问：“请按事件 ID 列出支持、不支持和证据不足的记录，并说明需要人工查看哪些证据。”问题只补充所选目标，不能代替未提供的数据源。
6. 查看证据缺口。没有事件、没有业务定义、无权限等会返回证据不足；此时服务端不向 DeepSeek 请求业务结论。
7. 证据充分且模型已配置时点击“开始分析”。回答只读，不执行控制。结果需与引用事件核对。

从记录/统计/报表进入时沿用筛选和固定时间窗，页内显示窗口；常规入口可选过去1/6/24小时。总量、分组、趋势和最近30条来自同次账本快照；超过100000条需缩小窗口。成功的场景分析保存当时的问题、窗口、筛选、证据与回答；管理员在下方“已保存的场景分析”回读或导出原始JSON，打开历史不会重新请求模型。

当前状态异常会作为健康信息显示，但完整历史仍可分析；历史结论不能被用来描述当前画面。统一分析的数字是筛选总数和本次返回记录的复核数，不是全站人数。

管理员在页面下方配置 HTTPS 模型服务地址、模型名及新密钥，保存并回读。密钥留空保留原值，清除需勾选相应选项；接口不回显密钥。“测试连接”分析平台状态，成功仅说明这次模型请求成功，不说明八场景准确率或 MES/EMS 已接入。

## 7. 确认报警和事件

平台报警和视频事件是两类记录：

- 平台报警在 `/alarms` 查看当前事件身份、状态和触发时间，再使用有权限的确认操作。并发更新可能使旧确认失效，应重新读取后核实。
- 视频事件在场景账本点击“确认此事件”。确认只作用于该 eventId，服务器回读确认时间后显示已确认；重复确认不新增事件。
- 确认表示操作员已处理或核查，不会把 VLM 的“证据不足”自动改为“支持”，也不代表现场危险消失。

无待确认报警时可以检验空状态，不能记为已完成真实 ACK 现场验收。真实 ACK 仍需在受控、有真实报警的条件下测试。

### 7.1 统计、报表与通知

监控数据看板从场景账本聚合候选数、小时趋势、复核与人工知晓状态。巡视不计入事件，候选总数不等于独立事故数。完整JSON导出保留筛选、窗口、生成时间、分组、趋势和全量事件，不受当前页30条影响；目前没有CSV导出入口。

报表编辑器可选择八场景综合、单场景或任意多场景子集（勾选组合，全不选会阻止保存），按源、镜头、子类型、复核/知晓过滤；汇总、趋势和完整明细使用同次快照，保存后重开不会把子集还原成全部。日/周/月使用站点生产时间窗（默认08:00边界），需核对预览中的起止与时区。手动生成请求被接受后页面会提示“生成完成”或“生成失败”及错误信息，异步失败不会一直显示成功；历史图片保留事件文件标识，不替换为当前帧。

通知订阅选择“八场景事件订阅”，至少选择一个场景和一个阶段；通知列表会显示订阅的场景/阶段范围，编辑保存后范围不会丢失。子类型填写账本中的标识，多个用英文逗号分隔，留空表示全部。首次启用、重新启用或修改范围只消费此后新事件，每订阅/eventId/阶段去重，失败最多尝试3次；网络超时可能使收件端重复收到。候选提醒不等于事故确认，复核提醒需同时阅读结论与限制。实际SMTP收件测试须使用已授权的接收配置。

## 8. 清零、重启与交班

“全部计数清零”会要求再次确认，影响当日与累计计数投影，保留事件历史、证据和确认记录。请先记录清零原因、操作者、清零时间；清零不是删除历史，也不是消警。失败时检查回读，不能仅根据按钮响应认为成功。

交班至少留下：双源在线状态、最近更新时间、门口应用版本、当前模型/复核错误、未确认事件、证据缺失、计数截点和待处理事项。关闭启动器前确认允许短暂停止业务；正常 Ctrl+C 会回收其启动的子进程。不要在数据库写入时直接复制一个文件当作完整备份。

## 9. 其他业务页面

- 设备：建立连接和标签后，核对协议、数据类型、采集质量和时间；连上设备不证明所有点位正确。实际现场写点须遵守操作权限。
- 数据展示 / 报表：先核对历史存储覆盖范围、查询时间、空值和质量，再解释统计。没有历史不补造趋势。
- MES / EMS：当前看板含静态样例；真实接入要配置对应模块定义和可见历史标签。AI 返回缺少定义时应补接入，不应要求模型生成数值。
- 流程 / 脚本 / 编辑器：属于配置或执行能力，修改前备份。统一 AI 不会代替这些页面执行动作。
- 旧 CHM / 帮助：只供旧版本参考。本轮新增记录页和真实性边界以本目录当前手册为准。

## 10. 常见问题

| 表现 | 核对方法 |
|---|---|
| 门口方向线未确认 | 按第4节检查实际标定、保存版本和 worker 回读；未完成前零记录正常 |
| 复核完成但证据不足 | 查看 verdict / limitations；补连续过线、静止时长或清晰图像 |
| 统一分析没有事件 | 核对目标、时间窗、权限、账本入库；巡视不产生事件 |
| 红外出现人数或安全帽提示 | 排查源绑定；T1 应保持独立辅助分析 |
| 当前画面正常、历史图片打不开 | 查事件 ID 对应文件与权限；禁止用实时帧替代 |
| 401 / 403 | 重新登录 / 联系管理员；检查角色和安全模式 |
| 版本冲突 | 重新加载当前标定，再核对现场后保存 |
| 模型超时或 CUDA 故障 | 保存错误码与时间，按部署维护手册排查进程和显存 |
| MES/EMS 有数值但 AI 缺定义 | 看板样例与真实定义接入分开，先完成后者 |

发现问题时提供版本、入口、时间、场景、事件 ID、预期/实际和脱敏错误码。不要发送密码、完整 token、含凭据 RTSP URL 或完整数据库到公共问题区。
