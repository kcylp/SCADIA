## 3. 仍开着的事项（如实陈述）

### 3.1 UI —— **HTTP 层 / 实时层 / 渲染层均已验证；只剩浏览器交互层**

**已确证为环境限制**（三轮尝试、多条路径全部失败）：

| 尝试 | 结果 |
|---|---|
| Chrome headless 直接访问 `http://127.0.0.1:1899/` | 服务端日志**零请求**（13→13 行） |
| 加 `--no-proxy-server` | 仍零请求 |
| 指定 `--proxy-server=http://127.0.0.1:7897`（代理确认存活） | 仍零请求 |
| 改用局域网 IP | 仍零请求 |
| 对照组：Chrome 渲染 `data:` URL | **正常**（浏览器本身没问题） |
| 对照组：PowerShell 请求同一 URL | **200**（服务端没问题） |

**结论**：本沙箱的 headless Chrome 无法访问本机网络，非我方代码问题。需要在你本机或任一联网机器上人工走查（步骤见验证记录 §9.3）。
