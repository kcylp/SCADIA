## 1. 目的与一处更正

评审原文 L263-299 要求把品牌迁移定义为**可复跑、可回滚的版本迁移**。**行动要求全部采纳。**

**但需更正一处技术前提**（评审原文 L279-283）：该文假设数据库运行在 WAL 模式，因此"改后缀可能丢失已提交事务"。
**实测**：本项目**主库未启用 WAL**——`runtime/project/prjstorage.js:65-67` 与 `runtime/alarms/alarmstorage.js:45-48` 均未设置 `journal_mode`（SQLite 默认 rollback journal）；全库 `PRAGMA journal_mode` **仅在 `runtime/calibration/calibration-storage.js:158` 命中一次**。
→ 因此**该条前提不成立**，但**结论保留**，理由有二：
1. 本工程**已有一处开 WAL**（校准库），风险非纯理论；
2. **实测发现一个同源的、真实存在的相邻缺口**：`runtime/storage/sqlite/index.js:484` 的**归档滚动改名只搬主库文件，不搬 `-wal`/`-shm`**（`:424-429` 只清理了 `-journal`）→ 台账 **L-11**。

## 3. 迁移流程（MUST，六步）

> 每一步 MUST 可独立执行、可观测、可回滚；MUST NOT 存在"一步到位、失败即半成品"的操作。

| 步 | 动作 | 必产出 | 失败处置 |
|---|---|---|---|
| **1 识别** | 识别工程版本、数据库版本、**新旧文件冲突**（同时存在 `.fuxap.db` 与 `.scadiap.db`） | 迁移清单（源→目标、数量、大小、mtime） | **中止**，不静默覆盖任一份 |
| **2 停写** | 停止相关写入；采用 **SQLite 支持的安全备份/关闭流程** | 停机确认、锁获取记录 | 中止；已停写须能恢复 |
| **3 备份** | 生成备份（含**伴随文件**：`-journal`、`-wal`、`-shm`） | 备份路径 + 校验和 | 中止 |
| **4 暂存转换** | 在**暂存位置**完成转换，**验证完整性、记录数、Tag 引用** | 校验报告（逐库：表数、行数、tagId 集合、悬空引用数） | 删除暂存，原库不动 |
| **5 统一切换** | 全部库**一起**切换（不得出现"工程库已换、报警库未换"） | 切换记录（各库切换前后指纹） | 回滚到第 3 步备份 |
| **6 恢复与验证** | 启动并验证读写；保留回滚窗口 | 验证报告 + 回滚说明 | 回滚 |

**硬性约束**：
1. **原子性**：第 5 步 MUST 是"全成或全不成"；任一库切换失败 MUST 全部回滚（评审原文 L285-288）。
2. **伴随文件**：凡涉及 SQLite 文件搬移，MUST 处理 `-journal`/`-wal`/`-shm`，并 MUST 在数据库**已关闭**状态下操作（评审原文 L281 的正确内核）。
3. **幂等**：重复执行 MUST 安全（已迁移则跳过并报告，不重复转换）。
4. **可回滚**：MUST 保留原始文件直到验证通过；MUST NOT 静默覆盖任意一份数据。
5. **文件名兼容**：若需支持旧文件名，MUST 采用 **"新名优先、旧名回退，且两者并存时报错"** 的策略，MUST NOT 静默择一。

## 4. 品牌标识迁移（与数据库迁移分开）

评审原文 L272-277：**品牌名 ≠ 机器身份**。

1. **显示品牌**（FUXA→SCADIA）与**协议/数据身份**（工程类型标识、驱动标识、OPC UA 命名空间、脚本常量）MUST 分开处理。
2. 旧标识的识别 MUST 在**工程加载边界**统一完成（转成稳定内部标识），MUST NOT 让各模块自行判断旧品牌字符串。
3. 现状 `device.js:36-38` 只保护**经过该入口**的调用；导入导出、离线迁移、工程校验、插件加载若绕过该入口仍不兼容 → MUST 补齐或明确声明不支持。

## 5. 验收门禁

| 门禁 | 方法 | 通过条件 |
|---|---|---|
| **G-MIG-1 旧工程** | 用旧品牌工程启动 | 正常加载；Tag/报警/趋势/脚本引用不失效 |
| **G-MIG-2 新旧并存** | 同时放置新旧文件名 | **明确报错或明确择一并记录**，不静默覆盖 |
| **G-MIG-3 WAL 存在** | 人为开启 WAL 后迁移 | 已提交事务不丢；伴随文件被正确处理 |
| **G-MIG-4 文件占用** | 迁移时保持文件被打开 | 检测并中止，给出明确原因 |
| **G-MIG-5 中断恢复** | 在第 4/5 步强制中断 | 可恢复到一致状态；无半迁移残留 |
| **G-MIG-6 重复执行** | 连续执行迁移两次 | 第二次安全跳过并报告 |
| **G-MIG-7 双库一致** | 工程库与报警库 | 切换原子；不存在一新一旧 |
| **G-MIG-8 Tag 引用完整性** | 迁移前后比对 tagId 集合与引用 | 集合一致；**零悬空引用** |
| **G-MIG-9 归档伴随文件**（L-11） | DAQ 归档滚动改名（`sqlite/index.js:484`） | `-wal`/`-shm` 被正确搬移或先完成检查点；无数据丢失 |

## 6. 与既有结论的关系

- 既有结论【阻断-1】（tagId 跨库迁移保真）与本规范**互补**：本规范管**文件与流程**，阻断-1 管**标识**。两者 MUST 同时满足（台账 L-04、L-05）。
- 评审原文 L299 要求的验收项（旧工程、新旧并存、WAL、占用、中断、重复执行、双库一致）**已全部纳入 §5**。

- 本规范**不构成改码授权**。
