## 3. 本次发现并修复的存量缺陷（**均非本次改动引入**）

### 3.1 内存报警检测完全无法触发（最严重）

- 报警引擎读 `tag.ts` 当采集时间；**全库从未有任何代码写过 `ts`**，驱动一律写 `tag.timestamp`（20 处）。
- 后果：`ontime = undefined` → `ontime + checkdelay*1000 <= time` 恒为假 → **一条实时报警也产生不了**。
- 修复：改读 `tag.timestamp`，缺失时回退到检查时刻。证据：插桩输出 `rc=false ontime=undefined ts=undefined`。

### 3.2 测试隐式全局 expect

- 4 个文件写 `global.expect = `；`runtimeUtilsTypes.test.js` **完全没声明却直接用**（靠泄漏存活）。
- 后果：测试相互依赖、依赖文件加载顺序。修复：全部改为顶部 require(chai)。

### 3.3 客户端根本无法编译

- `_models/device.ts` 在品牌化时把常量 `SCADIAServer` 改名为 `ScadiaServer`，但 `project.service.ts` 与 `tag-options.component.ts` 仍按旧名导入 → **TS2724，`ng build` 直接失败**。
- 修复：补 `export const SCADIAServer = ScadiaServer;` 兼容别名，不动 20+ 处调用点。
- 证据：修复前构建日志含 TS2724；修复后 error TS 计数为 **0**，`dist/` 产出 350 文件。
