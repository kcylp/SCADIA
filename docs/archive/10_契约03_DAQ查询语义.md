# 契约 03 · DAQ 查询语义契约 v1

> 状态：**草案**（待批准生效）｜ 覆盖意见：Codex 3 ｜ 台账：L-14

## 1. 目的

架构原文 L155 主张"AI 只依赖 tagId + 时间范围，换存储后端零改动"。
评审原文 L128 指出：`getHistoricalTags(tags, from, to)` **只说明了调用形式**，没有说明**不同后端必须提供哪些相同的结果语义**。
**本契约保留该门面（不绕开 DAQ），补足结果语义**，使"换后端零改动"成为**可验证命题**而非声明。

## 2. 现状（实测）

| 事实 | 证据 |
|---|---|

## 3. 规范性要求（结果语义）

### 3.1 必须版本化（MUST）
1. 查询请求 MUST 携带语义版本（建议 `v: 1`），或由门面固定并对外声明版本。
2. 结果 MUST 回显**实际生效的语义参数**，使调用方可判断自己拿到的是什么。

### 3.2 时间语义（MUST）
1. **时区**：请求时间 MUST 明确为 UTC epoch 毫秒；返回时间 MUST 同时给出 epoch 与 ISO-8601（含偏移）。
2. **精度**：必须声明归档分辨率（存储的最小时间粒度）。
3. **区间开闭**：MUST 明确定义为 **[from, to)**，并在契约测试中断言边界行为。
4. **时间基准**：必须声明采集时间戳的来源（设备时间 / 平台接收时间），以及两者是否可能相差。

### 3.3 数据语义（MUST）
1. **原始点 vs 聚合点** MUST 显式区分（请求参数与结果标记都要有）。
2. **重复点、乱序点、迟到点**的处理 MUST 明确定义（建议：按时间升序去重，保留策略明确；迟到点若进入已返回区间，必须在后续查询中一致可见）。
3. **缺失值**：
   - **默认 MUST NOT 插值**；
   - 如需插值 MUST 显式请求，且结果 MUST 标记哪些点是插值产生的；
   - **MUST NOT 把缺失补成正常值**（评审原文 L156）。
4. **质量码** MUST 随点返回（引用既有质量语义），**"坏质量点"与"无点" MUST 可区分**。
5. **单位与元数据版本** MUST 随结果返回（单位、标定版本——呼应契约 02 §4.4），使"昨天的数据不用今天的单位解释"。
6. **分辨率声明**：若结果经过聚合/降采样，MUST 返回实际分辨率，供调用方判断适用性（评审原文 L157："小时级归档不能被包装成具备秒级异常预测能力"）。

### 3.4 缺口与状态（MUST）
结果 MUST 显式区分以下情形，**不得统一为"空数组"**：

| 情形 | 语义 |
|---|---|
| 查询区间内该 Tag 无归档记录（值未跨死区） | `no-data` |
| 该 Tag 未启用归档 | `daq-disabled` |
| 该 Tag 不存在 | `unknown-tag`（**并报错，不静默**） |
| 归档后端不可用/查询失败 | `backend-error`（**并报错**） |
| 采集在区间内中断（可判定时） | `collection-gap` + 缺口区间 |

并 MUST 提供**缺口清单**（`gaps: [{from, to, reason}]`）与**采样密度/缺失率统计**。

### 3.5 分页与一致性（MUST）
1. 大范围查询 MUST 支持分页；多页结果 MUST 满足：**并集 = 单页查询结果**（不得丢点、不得重复计点）。
2. MUST 提供稳定排序（按时间升序；同时间戳的次序规则需定义）。

### 3.6 资源与可用性（MUST）
1. 查询 MUST 受限于：**最大时间范围、最大返回点数、最大并发数、最大执行时长**；超限 MUST 返回**明确错误**（而不是静默截断）。
2. 查询 MUST 支持**取消**。
3. 查询 MUST NOT 与实时归档/采集争抢到影响采集的程度（约束见契约 01 §3.3）。
4. 长查询 MUST 与实时写入路径隔离（独立并发预算）。

## 4. 验收门禁

| 门禁 | 方法 | 通过条件 |
|---|---|---|
| **G-DAQ-1 跨后端契约测试** | **同一组查询**在 SQLite / InfluxDB / QuestDB（及裁决后的 TDengine）上执行 | 归一化后的结果**逐条一致**（含质量码、缺口、排序、边界） |
| **G-DAQ-2 边界语义** | `[from, to)` 边界点、同时间戳多点、区间为空 | 行为与契约一致且**在所有后端一致** |
| **G-DAQ-3 不可区分性消除** | 构造 5 种情形（§3.4） | 每种返回**不同的、可编程判定的**状态，不再都是空数组 |
| **G-DAQ-4 不插值** | 请求含缺口的区间 | 默认结果无凭空点；插值仅在被请求时出现且被标记 |
| **G-DAQ-5 分页一致性** | 分页取全量 vs 单次取全量 | 并集一致 |
| **G-DAQ-6 限额与取消** | 超范围、超点数、超并发；发起后取消 | 均返回明确错误/成功取消；**采集延迟不受影响** |
| **G-DAQ-7 换后端代码不改** | 仅改配置切换后端 | 调用方代码零改动（**与"旧历史仍可访问"分开验收**，评审原文 L160） |

## 5. 与 AI 消费方的接口约定

1. AI 分析 MUST 在**执行前**校验：采样密度、缺失率、时间基准、单位/标定版本、数据适用性（评审原文 L157）。
2. 数据**不满足适用性时**，MUST 返回"证据不足/数据不适用"，MUST NOT 继续产出预测。
3. 分析查询 MUST 使用受限并发预算，不得与实时链路共享无界队列。

## 7. 明确不做

- 不绕开 DAQ 门面让 AI 直连物理库（保留架构原文 L138 的取舍）。
- 不在本契约内做历史数据迁移（评审原文 L160：**配置切换本身不负责历史迁移**）。
- 本契约**不构成改码授权**。
