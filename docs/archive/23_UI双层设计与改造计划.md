## 0. 先说判断

**这套软件要当成两个产品来做，它们的用户、环境、验收标准都不一样。**

| | A 平台软件（组态/管理态） | B 当前工程（运行/监视态） |

| 谁用 | 电气/自动化工程师、系统管理员 | 值班员、调度、领导参观 |

## 2. 现状体检（实测证据）

### 2.1 画面是"死的"——这是"卡住"的真正原因

实测工程库（\`project/_appdata/project.scadiap.db\`）：

| 项 | 实测值 | 含义 |
|---|---|---|
| views | **8** 个 | v_zc_g1 ~ v_zc_g8 |
| 每个画面的 items（控件） | **0** | 一张画面里没有任何控件 |
| devices | **1** 台，类型 SCADIAServer，**0 个标签** | 没有任何数据源 |
| alarms | 0 | 报警表空 |
| 画面内容 | 1 张背景大图（1770×993） + 手画的 rect | 是**效果图**，不是画面 |

也就是说：**当前 8 个画面是"背景图 + 手画矩形"，没有控件、没有绑定、没有数据。** 屏幕上不会有任何东西在动——这是"看着像卡住"的根因，不是性能故障。

浏览器实测（headless Chrome，1920×1080）：
- pageerror **0**，失败请求 **0**，HTTP ≥400 **0** —— 前端没报错。
- 首页 DOM 只有 326 个节点，报警面板显示"0 的 0"，3 张报警卡只有标签没有值。

### 2.2 平台侧的首屏很重

| 指标 | 实测 | 问题 |
|---|---|---|
| 脚本传输量 | **24.9 MB**（vendor.js 约 18 MB） | 现场工控机/笔记本首次打开很慢 |
| DOMContentLoaded | **3.84 s** | 首屏接近 4 秒 |
| 最长单次长任务 | **2583 ms** | 一次 2.6 秒的阻塞，期间界面完全无响应 |
| 其余长任务 | 669 / 184 / 75 / 64 ms | 连续卡顿 |
| 加载后交互 | 6.4 ms 往返 | 加载完是流畅的 |

**判断**：不是"运行中卡"，是"**启动时卡**"。车间笔记本（尤其是 8G 内存 + 机械盘）体验会很差。

### 2.3 导航只露出 3 项，与后端严重不对应

未登录实测可见菜单：**编辑器 / 实验室 / 首页**（3 项）。

而前端实际已有 **25 条路由**，后端也有完整的域。差距不在能力，在**信息架构与项目配置**：工程的 \`general\` 表只有一行 \`version\`，**没有导航配置**，于是回退到默认的 3 项。

### 2.4 分辨率适配：现在必然出黑框

- 画面 profile 是**固定像素画布**（1770×993 或 1920×1080）。
- 现有缩放逻辑（\`scadia-view.component.ts\`）把旧 auto-resize **映射成 contain**——contain 保持比例，两侧/上下就是黑边。
- 平台外壳用 px 固定尺寸，没有跨分辨率规范。

**用户要求"无论接谁都能满屏、没有黑框"，靠调缩放系数是做不到的，必须改渲染模型**（见第 5 节）。

## 5. 跨分辨率：满屏、无黑框（硬要求）

### 5.1 目标设备

| 场景 | 分辨率 | 备注 |
|---|---|---|
| 笔记本 | 1366×768 / 1536×864 / 1920×1080 | 常带 Windows 125%/150% 缩放 |
| 台式/值班 | 1920×1080 | 主力 |
| 值班大屏 | 2560×1440 / 3840×2160 | 32 寸以上 |
| 带鱼屏 | 3440×1440 / 2560×1080 | 不能留空 |

### 5.2 三条硬规则

1. **外壳流式**：不用固定像素画布。\`html,body{height:100%}\`，应用根用 \`100dvh\`；栅格用 \`repeat(auto-fit, minmax(...))\`；间距/字号用 \`clamp()\` 跟视口走。**任何分辨率下页面背景都铺满**，不出现白边或黑边。
2. **画面分两层**：
   - **底图层**：背景大图 / 装饰矢量 → \`object-fit: cover\` 或 SVG \`preserveAspectRatio="xMidYMid slice"\`，铺满、裁边、不留黑框。
   - **内容层**：真正的控件（KPI、趋势、报警卡、视频格）用 **CSS Grid 重排**，不跟着底图缩放。**这是"无黑框"的关键**：画面不再是一张固定尺寸的画布，而是一组会重排的面板。
3. **数值缩放跟 devicePixelRatio 走**：Windows 125%/150% 下不糊、不溢出；字号不用 px 硬编码，用令牌 + clamp。

### 5.3 大屏模式

提供 \`?kiosk=1\` / F11 全屏的**演示态**：隐藏导航、字号整体放大 \`--ui-scale\`、报警强调，适配展厅与领导参观。

### 5.4 验收方法（可复现）

用本机 headless Chrome 在 1366×768 / 1920×1080 / 2560×1440 / 3440×1440 四种视口逐一截图，**断言：① 无滚动条横溢；② 页面四边无空白边带；③ 关键内容不被裁掉**。截图留档作为证据。

## 10. 内置素材库：把现有底图变成可复用资产

**用户要求：这些底图要变成固定可调取的库，集成进软件，后续做别的工程直接用。**

### 10.1 为什么现在做不到

底图目前是工程私有的：project/_images/<hash>.png，文件名是内容 hash，没有任何说明。
结果是：新工程要用同一张底板，只能靠人记得文件名、手工拷过去；换个人就找不到。

### 10.2 落点（实测过的定位规则）

main.js:58 决定 rootDir = __dirname（可用 --userDir / 环境变量覆盖，当前实例就指向工程目录）。所以分两层：

| 层 | 路径 | 归属 | 说明 |
|---|---|---|---|
| 软件内置库 | <appDir>/_assets/ | 随软件走 | 换工程、换现场都在 |
| 工程私有图 | <rootDir>/_images/ | 随工程走 | 现状不变 |

### 10.3 设计

1. **库 = 目录 + 清单**：_assets/manifest.json 描述每一张（id、中文名、分类［底图/标题栏/列表/图标］、尺寸、文件、缩略图、标签、版本）。文件名保持人可读，例如 底图_主底板_1770x993.png，不再只有 hash。
2. **发布**：/_assets 静态挂载（照 main.js:473 的 /_images 写法）+ GET /api/assets 返回清单。
3. **编辑器里一个「素材库」面板**：按分类浏览、看缩略图、点一下插入当前画面。
4. **用时是拷贝，不是引用**：落进当前工程的 _images/。理由：现场工程要能整个拷走、离线跑；引用会让工程依赖某一版软件。代价是库更新不会自动进老工程 —— 这是对的，老工程本来就不该被静默改画面。
5. **首批入库**：就是第 9 节清点出来的那批（主底板 1770×993、启动页 1920×1080、标题栏 1920×87、左列表 364×993 等），共 11 张有尺寸的资产加小素材。

### 10.4 与守卫的关系

第 9 节新增的 projectAssets.test.js 已经保证「画面引用的资源都在盘上」。素材库落地后同一条守卫自然延伸：清单里声明的每个文件都必须存在，否则编辑器会给出一个坏缩略图。

## 11. 组态开发体验：让它像专业 SCADA，而不像画图软件

**用户要求：scada 开发部分必须非常像专业的 scada 操作方式，工控技术人员会使用。**

### 11.1 先理解工控工程师的肌肉记忆

一个干了十年的自控工程师，打开任何组态软件（WinCC / iFIX / InTouch / 组态王 / 力控 / Ignition），手会自己去找这七样东西。缺一样他就觉得「这软件不专业」：

| # | 他要什么 | 在哪 | 为什么是肌肉记忆 |
|---|---|---|---|
| 1 | **工程树**（左，常驻） | 画面 / 设备 / 变量 / 报警 / 报表 / 脚本，右键出菜单 | 从树进一切，不进菜单栏 |
| 2 | **工具箱 / 图库**（左，常驻） | 基本图元 + 工业元件（泵阀门罐电机皮带） | 拖拽放置，不是弹窗选形状 |

### 11.2 现状（实测）与差距

已经有的（正面资产）：
- 画面列表 editor-views-list、画面属性 view-property、布局与导航配置 layout-property、图表/曲线/卡片配置、标签对配置 tags-ids-config、脚本 access、向导 onboarding-wizard、应用设置。
- 缩放模式（含 cover/stretch/width）与自动适配引擎已经写好。

**核心差距是一句话：现在的编辑器是「对话框驱动」的图形编辑器，不是「面板驱动」的组态环境。**

| 项 | 实测证据 | 结论 |
|---|---|---|
| 常驻工具箱 | 全编辑器只有 3 处 toolbox 类名，且**都在对话框里**（graph-config、chart-config、view-property） | ❌ 没有左侧常驻工具箱 |
| 常驻属性网格 | 属性靠**逐个弹窗**（view-property / graph-config / chart-config / card-config）改 | ❌ 没有选中即显的属性网格 |
| 变量选择器 | 模板中只有 tags-ids-config 里 2 处绑定；**没有通用取变量控件** | ❌ 绑定靠手填 id |
| 快捷键 | 整个 editor 目录对键盘的处理只有 **1 处**，且是无关的输入框回车 | ❌ 无 Ctrl+C/V/Z、无方向键微调、无 F5 |
| 工程树 | 有 editor-views-list（画面列表），但设备/变量/报警不在同一棵树里 | ◐ 半套 |

### 11.3 改造原则

1. **面板常驻，对话框退位**：左工具箱 + 右属性网格常驻；只有「动画连接」「脚本编辑」「变量详细定义」这类复杂子编辑器才弹窗。
2. **一切皆可右键**：树节点、画布对象、属性行都出上下文菜单（新建/删除/重命名/属性/复制/锁定）。
3. **键盘优先**：先把 Ctrl+C/V/X/Z、Del、方向键微调、Shift 等比、Ctrl+G 组合、F5 运行做出来 —— 这一条对「像不像专业软件」的权重，比配色高得多。
4. **变量选择器统一**：做一个可复用的变量选择器组件（搜索 / 按设备过滤 / 显示类型与量程），所有绑定字段都用它。
5. **运行态预览内嵌**：编辑器里一键切运行（F5），不跳页；改完立刻看。
6. **不推翻已有对话框**：现有 view-property / graph-config 等全部保留为「详细设置」，只是不再是唯一入口。

## 12. 工程侧（8 个画面）的实测结论：它们是「一块屏的三件零件」

### 12.1 尺寸算术揭示了真实意图

| 画面 | 尺寸 |
|---|---|
| v_zc_g3 顶部标题栏 | 1920 × **87** |
| v_zc_g8 左列表 | **150** × 993 |
| v_zc_g1 AI检测 / g2 数据展示 / g4 视频监控 / g5 报警查询 | **1770** × 993 |

**150 + 1770 = 1920，87 + 993 = 1080。** 所以这 8 张不是 8 个屏幕，而是**一块 1920×1080 屏幕的零件**：标题栏 + 左列表 + 内容区。
工程里 `_images/zc/embed_*.html`（1.9~2.5MB，未被子画面引用）正是上一轮尝试把它们拼成一整屏的产物，印证了这个意图。

### 12.2 已实测：拼接本身成立，但**零件是空的，拼出来还是空的**

我把 g3 + g8 + g1 合成为一张 1920×1080 的新画面，写进工程副本、起临时实例实测渲染：
- 标题栏正确横贯顶部，内容区正确落在 x=150、y=87，**无重叠、无错位** → 拼接模型成立

**结论：靠重排现有零件拿不到 D1 的质量，因为零件本身没有内容。P5 的真正工作量是「逐张写内容」，不是「重新拼」。**
这也和 12.3 的数学一致：8 张画面 items 全为 0、工程 0 个标签 —— 没有任何东西能驱动它们。

## 15. 组态编辑器实测清单（子代理全量扫描，**更正第 11 节**）

### 15.1 先更正我自己的两处误判

第 11 节我说「编辑器几乎没有键盘处理、没有属性面板、没有变量选择器」。**这三条都错了**，因为我当时只 grep 了 Angular 的 `.ts`，**漏掉了随包发行的 svg-edit 库**（`assets/lib/svgeditor/scadia-editor.min.js`，自称 `editor v2.9.12-173`）——快捷键表就在那个包里。

| 我说过的 | 实际 |
|---|---|
| 无快捷键 | **有**：V/Q/L/R/E/P/T 工具键、Del、Ctrl+Z/Y、Ctrl+C/V/X、Ctrl+D 克隆、Ctrl+G 组合、Ctrl+A、Ctrl+[ / ] 层级、方向键移动 1px、Shift+方向键 10px、Tab 切层 |
| 无属性面板 | **有**：选中即出右侧浮动属性条（定位/对齐/边框/标记/超链接/事件），底部有填充/描边取色器与调色板 |
| 无变量选择器 | **有**：`flex-variable` 是带自动补全的变量选择器（按设备分组 optgroup）；旁边还有 `DeviceTagSelectionComponent`——可搜索、可按名称/地址/设备过滤、**并能当场新建标签**（支持 OPC UA/S7/Modbus/内建等十几种协议） |

**教训**：这个仓库有 vendored 第三方包（svg-edit、raphael、shapes.js）。只用 grep 扫第一方源码会系统性漏掉它们。

### 15.3 核实过的真实缺口（**这才是 E 阶段该做的**）

| 缺口 | 证据 |
|---|---|
| **没有图层/对象树面板** | `layerlist|layerpanel|svg_layers` 在 `app/editor` **0 命中**；图层右键菜单的 markup 在（`editor.component.html:1138-1151`）但**没有任何东西能打开它**——死代码 |

### 15.4 对 E 阶段计划的影响

原 E-1「左工具箱 + 右属性网格常驻」应下调优先级——**右侧属性条已经有了**，只是浮动、且不含控件参数（控件参数在模态框里）。

**修正后的 E 优先级**：

| 新序 | 内容 | 理由 |
|---|---|---|
| **E-1** | **图层/对象树面板**（含每层显示/锁定） | 缺口最大，且死代码已备好（`#cmenu_layers`）；大画面没有图层树无法维护 |
| **E-2** | **打开那个 NOT USED 的参数对话框**（网格尺寸/捕捉步长/标尺/单位），并把网格与捕捉解耦 | 东西都在，只是没入口——**投入产出比最高** |

| **E-5** | 智能参考线/对象吸附 | 专业感的关键，但工作量大 |
| **E-6** | 导出 PNG/PDF 接线；翻转按钮接线 | 收尾 |
| **E-7** | 112 个 P&ID 符号重新分组（把死文件接上） | 可用性问题，不是缺失 |
