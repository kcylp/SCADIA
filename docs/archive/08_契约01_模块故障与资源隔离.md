# 契约 01 · 模块故障与资源隔离契约 v1

> 状态：**草案**（待老板批准后生效，批准前不作为实现依据）

## 1. 目的与范围

评审原文 L71 要求补充的是"**哪个模块失败时，其他模块具体怎样继续运行**的契约，而不只是目录划分"。
本契约定义**运行进程内的模块隔离与资源所有权语义**。范围：SCADIA Server 单进程内的子系统（设备驱动、视频/AI、DAQ、报警、调度、脚本、OPC UA Server、Node-RED 集成）。
**不在范围**：微服务化改造（评审原文 L68 明确"普通业务模块不必全部微服务化"）。

## 2. 现状（实测）

| 事实 | 证据 |
|---|---|
| 视频初始化失败**不阻断**采集 | `runtime/index.js:99-101` `cameras.init(...).catch(...)` 仅记日志 |
| GB28181/AI 子模块各自 catch，占用端口不致命 | `cameras/index.js:24-34`（注释明写 opt-in 理由） |
| 退化到**同进程、同事件循环**，无隔离 | 无 worker/子进程边界；`runtime/index.js:143-147` 全部挂在同一 EventEmitter 上 |
| 存在**全量扫描**型负载 | `opcua-server/index.js:530-535` `refreshTags()` 遍历全部已发布 Tag；`:549-551` 默认 1000ms、下限 200ms |
| 总线**无界广播** | `runtime/index.js:608-626` `io.emit(...)` 面向全部前端，无背压 |
| 驱动扩展**无注册表** | `device.js:569-601` `loadPlugin` 为 if/else 链（→ L-15） |

**结论：**"初始化失败不阻断"**已实现**；**"过载不拖慢""退出不污染共享资源""重启不重复注册"尚未有契约与门禁**。

## 3. 规范性要求

### 3.1 模块生命周期（MUST）
1. 每个子系统 MUST 提供 `init(settings, logger, runtime)` 与 `stop()`，且 **`init` 的失败 MUST 被调用方捕获**，不得导致 runtime 启动失败。
2. `stop()` MUST 是**幂等**的（重复调用不抛错、不重复释放）。
3. 模块 MUST 只释放**自己创建**的资源（监听器、定时器、连接、句柄、DB）。
4. 模块 MUST NOT 在 `stop()` 中释放共享资源（如 `runtime.events`、`io`、`socketPool`、`socketMutex`）。

### 3.2 监听器与定时器所有权（MUST）
1. 所有 `setInterval`/`setTimeout`/`events.on`/`socket.on` MUST 记录可撤销句柄，并在 `stop()` 中撤销。
2. 定时器 MUST 调用 `.unref()`（不阻止进程退出）——**现状参考**：`opcua-server/index.js:545,554` 已正确 `unref`。
3. **重启一次不得产生重复注册**。验收方式：`init→stop` 重复 N 次后，`tag-value:changed` 监听器数量 MUST 保持不变。

### 3.3 资源所有权与配额（MUST）
1. **实时采集链 MUST NOT 同步等待**视频、AI、浏览器推送、OPC UA 发布、Node-RED 等非关键消费者。
2. 每个模块 MUST 声明并在实现中强制以下配额（可为可配置项，但**必须存在默认值**）：
   - **并发上限**（同时进行的请求/扫描/查询数）
   - **队列上限**（排队项数）；**达到上限时的行为 MUST 明确定义**，只能是"丢弃最旧 / 拒绝新项 / 降级"，**不得无界增长**
   - **单位时间预算**（单次操作的 CPU/时长上限）
3. 长耗时操作（历史查询、全量扫描、报表）MUST 支持**分片或取消**，或 MUST 运行在**受限并发**下（建议：独立队列 + 并发≤N）。
4. 全量扫描类任务 MUST 有**节流**机制：单次扫描耗时超过阈值时 MUST 自动降频并记录告警日志。

### 3.4 总线按用途分流（MUST）
评审原文 L66 的要求。三类数据 MUST 使用**不同策略**，不得共用一条无界队列：

| 类别 | 实例 | 可靠性 | 策略 |
|---|---|---|---|
| **实时值** | Tag 值推送、趋势 | 可丢旧保新 | 每订阅者保留最新值；拥塞时**覆盖而非排队** |
| **可靠业务事件** | 报警产生/确认/恢复、操作日志 | 不可丢 | 有界队列 + 持久化 + 重试；溢出 MUST 告警 |
| **易失检测框** | AI 框叠加 | 可丢、可过期 | 直接覆盖；过期即清；**不排队、不落盘** |

### 3.5 健康与降级（MUST）
1. 每个模块 MUST 暴露可查询的状态（running/enabled/lastError/计数），供 `/api/diagnose` 使用。
2. 模块失联 MUST 表达为**该模块的降级状态**，MUST NOT 表达为"无异常"（与 AI 视频契约呼应）。
3. 降级 MUST 记录一条**结构化告警**（模块名、原因、时间、影响面）。

## 4. 验收门禁（可执行）

| 门禁 | 方法 | 通过条件 |
|---|---|---|
| **G-ISO-1 初始化隔离** | 注入一个必然失败的驱动/相机/OPC UA 配置启动 | 采集正常运行；失败模块状态为降级；日志含结构化原因 |
| **G-ISO-2 停止幂等** | `init→stop→stop`；`init→stop` × 5 | 无异常；监听器/定时器计数回到基线 |
| **G-ISO-3 视频过载** | 视频/AI 摄入灌入高频事件 | 采集周期抖动 < 阈值；报警延迟 < 阈值（阈值待定，见 §5 Q2） |
| **G-ISO-4 慢查询** | 发起数月范围历史查询 | 采集/报警延迟不受影响；查询可取消；超限被拒绝并有明确错误 |
| **G-ISO-5 慢消费者** | 模拟不读数据的 Socket 客户端 | 内存不无界增长；队列达上限时按 §3.3 定义行为处置并告警 |
| **G-ISO-6 重启不重复注册** | `init→stop` × 5 后触发一次 Tag 变化 | 下游只收到 **1 次**事件 |
| **G-ISO-7 驱动扩展** | 新增一个驱动（或模拟） | **不修改 `device.js` 核心分支**（依赖 L-15 注册表落地） |

## 5. 待定问题（需裁决或实测确定）

| # | 问题 | 处置 |
|---|---|---|
| Q1 | 配额的具体数值（并发/队列/时长） | 需现场规模（Tag 数、轮询周期、相机数）后压测定 |

## 6. 明确不做

- 不把普通业务模块微服务化。
- 不为"隔离"而改写既有驱动接口（驱动契约见 `02_PLAN_集成规划.md:603` 既有约定）。
- 本契约**不构成改码授权**。
