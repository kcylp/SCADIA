# SCADIA 部署维护手册

适用对象：Windows 工作站维护人员、研发、交付人员。本文随 2026-10-15 实现基线及八场景统一分析修订交付。命令假定从仓库根目录运行；PowerShell 与 Git Bash 的路径语法不得混用。运行配置和数据库保留本机，GitHub 保存源码与文档。

## 1. 交付组成和环境

| 目录/文件 | 内容 | 新机器是否自动获得 |
|---|---|---|
| source/server | Node 服务、API、驱动、SQLite 账本、测试 | Git 克隆获得源码；依赖另装 |
| source/client | Angular 界面与项目配置 | Git 克隆获得源码；需构建 |
| source/tools | 视频代理、检测、复核、事件桥接、检查工具 | 源码随库；Python/FFmpeg/模型另装 |
| docs | 本轮产品、操作、部署手册与历史文档目录 | 随库 |
| project | 现场工程、账号、设备、配置、日志、事件证据 | 不随源码；授权备份另行恢复 |
| models | 人体/姿态/安全帽/VLM 等权重 | 不随源码；离线预置并记录来源 |
| runtime | 可选便携 Node、Python、FFmpeg | 不随源码；自行安装或恢复授权运行包 |
| start-scadia.ps1 | 联合启动入口 | 随库；依赖上面实际环境 |
| deploy-scenes.ps1 | 当前 Windows 工程重启与版本端点探测 | 随库；不是安装器或测试替代品 |

当前现场入口为 `http://127.0.0.1:1881`，视频代理为 `127.0.0.1:1886`。1886 属于内部取帧组件；页面通过平台接口取帧。现场路径为 `D:\SCADIA-工作站迁移\SCADIA`，安装到其他目录需检查所有本地绝对路径。

Node 服务使用 npm 依赖和本地原生模块；Python 推理使用 PyTorch/Ultralytics/OpenCV，VLM 额外依赖 Transformers 等。GPU 需要匹配的 NVIDIA 驱动、CUDA 版 PyTorch和足够显存；CPU 可运行部分检测，性能另测。此仓库没有跨全部 Node/Python/CUDA 组合的兼容认证，迁移优先复制已验收环境版本并留存版本清单。

## 2. 新克隆与已有现场工程是两种部署

### 2.1 获取和构建源码

PowerShell 示例：

```powershell
git clone https://github.com/kcylp/SCADIA.git
Set-Location SCADIA
node --version
npm --version
Set-Location source\server
npm ci
npm run build
npm run test:lint
Set-Location ..\client
npm ci
npm run build -- --configuration production
Set-Location ..\..
```

有 lockfile 时使用 `npm ci`，不要为安装方便删除 lockfile。网络、原生模块编译或二进制下载失败时先保留错误，解决对应依赖再继续。`npm run build` 服务端执行 TypeScript 编译；Angular 构建输出在 `source/client/dist`。旧版安装资料可能写 `source/server/dist` 为 UI，本项目运行时优先检测该目录是否存在 `index.html`，存在时会覆盖 client/dist 的选择。升级时必须核对实际静态目录，避免新源码配旧 UI。

纯源码启动一个新的空工程：

```powershell
New-Item -ItemType Directory -Force project\_appdata | Out-Null
node source\server\main.js --port 1881 --userDir "$PWD\project"
```

首次启动会按默认值创建 settings.js 和必要数据。空工程不会凭空具有现场 HMI、摄像机、账号、门口标定、模型或 MES 数据。账号初始化按当前服务的初始化流程处理，不能沿用旧说明中的公开固定密码。默认配置不是生产安全配置；正式上线前配置授权账号、`secureEnabled` 和网络监听边界，重新验证读取/写入权限。

### 2.2 恢复已有现场

1. 核对备份所属工程、版本和时间；关闭相同工程的旧进程，确保数据库没有写入。
2. 把授权的 project 备份恢复到预期位置；不要用空工程覆盖现场 project。
3. 核对 settings、用户数据库、Tag/设备/历史数据路径、相机配置、代理配置、模型绝对路径、FFmpeg 路径。
4. 将本地模型放到配置指定目录；确认权重类型、文件大小和哈希。YOLO 权重与 VLM 模型各自验证，模型文件名不等于能力证明。
5. 安装本机依赖并构建界面；按第 3 节启动。
6. 先验证平台，再逐个启用相机代理、可见光检测、红外检测、VLM 和事件桥接。每启用一层核对输出与日志。
7. 原门口几何只有在相机位置、焦距、画面裁剪/旋转/镜像都一致时才可考虑复用；仍须走正反通行验证。

本轮没有完成全新空机器安装验收，以上命令依据仓库脚本与实际构建入口编写。已部署工作站的构建/测试证据见验收记录。

## 3. 启动、停止和更新

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-scadia.ps1
```

默认读取根目录下的 project。可用参数：`-Port 1881`、`-NoBrowser`、`-Sandbox`。Sandbox 使用 `runtime/sandbox-project` 的一次性副本，不替代生产配置；启动脚本会清理已有 sandbox 目录。正常运行缺少可选依赖时会输出跳过提示，主服务启动不等于所有 AI 子进程启动。

启动脚本依次检查运行目录，启动视频代理、事件桥接、可见光检测、红外检测、VLM，最后启动平台。Ctrl+C 结束脚本，finally 中停止该脚本启动的子进程。后台部署可用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-scenes.ps1
```

此命令会停止命令行包含当前完整仓库路径的 Node/Python 组件，再拉起 launcher，最多等待约30次探测 `/api/version`。这是中断性的本地重启，执行前让值班人员知道画面和分析会短暂停止。它不重编译前端，不备份数据库，不验证相机和推理；必须先构建、备份并在重启后检查。

升级顺序：备份现场 → 记录当前 commit → 取得源码 → 安装兼容依赖 → 服务端与客户端构建 → 测试 → 重启 → 回读版本、场景状态、门口版本、历史事件 → 业务验收。回滚使用备份源码/环境和匹配工程快照，不删除新现场数据来迎合旧版本。

## 4. 配置职责

以下文件位于本地 `project/_appdata`；包含凭据的文件禁止提交 Git。

| 文件/配置 | 职责 | 维护注意 |
|---|---|---|
| settings.js | 服务端口、监听、安全模式、存储和集成设置 | 对照 settings.default.js；改变端口要同步平台客户端配置 |
| ai-tracker.json | 可见光相机ID、取帧源、模型、检测/门口/场景规则、平台连接 | 门口只通过受校验保存流程确认；配置保存失败保留旧版本 |
| ai-tracker-thermal.json | 红外相机ID、取帧源、独立模型和输出 | streamKind 为 thermal；不要复制可见光几何 |
| vlm.json | 本地 VLM 目录、设备和预算 | model_dir 必须存在；默认 maxNewTokens=200；硬超时和输入预算受校验 |
| mjpeg-sources.json | 视频代理的源、认证和 FFmpeg 参数 | 可见光与红外各自配置；不要把含账号的 RTSP URL 写入公开文档 |
| video-events.json | 摄像机原生事件桥接 | 相机原生事件与视觉候选分开检查 |
| model-service.json（由配置服务管理） | DeepSeek 服务、模型和密钥 | 具体文件名以 model-config.js 为准；页面不回显密钥 |

可见光检测最小结构示意（不是现场配置；REPLACE 字段必须按实际替换）：

```json
{
  "cameraId": "REPLACE_VISIBLE_CAMERA_ID",
  "streamKind": "visible",
  "source": {"snapshot": "http://127.0.0.1:1886/snapshot/kuangqu1"},
  "model": "D:/SCADIA/models/yolov8n-pose.pt",
  "platform": "http://127.0.0.1:1881",
  "user": "REPLACE_AUTHORIZED_USER",
  "password": "REPLACE_LOCAL_ONLY",
  "targetFps": 8,
  "entryGate": {"enabled": false, "verified": false}
}
```

红外使用独立 cameraId、streamKind=`thermal`、snapshot 后缀 `kuangqu1-thermal`、独立输出文件与合适模型。完整可选项对照 `source/tools/scadia-ai-tracker.py` 的 DEFAULTS；未配置 source 时脚本有现场默认 RTSP 回退，迁移必须显式提供正确 source，避免误连默认地址。模型路径不存在时 Ultralytics 可能按名字尝试下载，离线部署应提前准备正确权重。不得复制示意门口点集并设为已确认。

Python 安装入口：

```powershell
python -m pip install -r source\tools\requirements-ai-tracker.txt
```

CUDA PyTorch 与 VLM 依赖按实际版本匹配安装，不能仅凭上面命令确认 GPU 可用。启动后看实际 device、模型路径、推理耗时和错误。`scadia-scene-review.py` 使用 ai-tracker.json 的平台连接领取逐事件复核任务；主平台离线或登录失败时须检查 ledgerStatus。

## 5. 运行数据与备份

`workDir` 为当前 userDir 下的 `_appdata`。应备份整个 project，而非只复制一个数据库文件：

- 用户/权限、项目定义、设备/Tag/报警配置和业务历史库；
- `_appdata/scene-events` 事件投递队列、持久事件数据库及复核结果；
- `_appdata/scene-evidence` 事件历史图片和连续帧；
- 计数投影与清零审计、门口配置与标定版本；
- `_images` 运行状态和需要保留的诊断图、`_logs` 必要日志；
- 另备模型/环境版本清单和授权外置模型。

停止该工程全部写入进程后复制 project 到带时间戳的备份目录。SQLite 如启用 WAL，应通过一致性备份或停机后连同数据库辅助文件处理，避免运行中只复制主文件。对副本核对文件数、大小、数据库可打开、历史事件数量、随机抽查图片、门口版本和账号登录。备份恢复测试应在隔离目录和不同端口执行，避免两个实例同时操作同一 project。

清零只改变统计投影，历史事件和证据保留。磁盘清理不属于清零；目前不保证事件证据自动归档/长期保留策略已经部署。设定容量、保留期和离线备份方案后再人工清理授权范围。

## 6. 健康检查和日志

先用浏览器或只读 HTTP 请求核对 `/api/version` 返回200，再登录管理员读取 `/api/ai/scenes`、`/api/ai/scene-events`。安全模式下未登录401、普通用户403属于权限结果，不是检测服务故障。不要在命令行明文输出 token。

场景健康重点：

1. visible/thermal 各有自己的 camera、streamKind、updatedAt，且持续前进。
2. 相机代理 `X-Frame-Time` 前进；有新状态不代表画面不是重复帧。
3. 检测 inferenceMs、会话和轨迹变化合理；断流后重新建立观察会话。
4. 门口 appliedCalibrationVersion 对应实际保存版本；没有 calibrationError。
5. 事件账本中场景、相机、发生时间、版本与实际测试动作对应。
6. 逐事件 reviewStatus、verdict、limitations 和诊断字段存在；巡视不覆盖事件复核。
7. HTTP delivery、ledgerStatus 和本地文件更新分别检查。`not_sent` 不能写成平台投递成功。

日志在 `project/_logs`：scene-launch、ai-tracker、ai-tracker-thermal、vlm、视频代理和桥接日志。日志可能含现场连接信息，提交支持材料前脱敏。GPU非法访问/OOM时要回收进程并按预算降低负载，不无限重试占满资源。

## 7. 故障处理

| 故障 | 排查顺序 | 恢复判据 |
|---|---|---|
| 1881 不响应 | launcher日志、端口占用、依赖、settings语法、数据库目录权限 | API200且应用可进入 |
| 新功能未出现 | 浏览器缓存、实际 httpStatic、server/dist 与 client/dist、重启旧进程 | 返回HTML/JS包含本轮入口，API结构相符 |
| 源离线/陈旧 | 1886代理、FFmpeg、相机网络/认证、updatedAt/frameAt | 两源分别连续前进 |
| 事件未入账 | scene-events投递队列、畸形事件隔离、DB权限、sceneId/kind/source | 合法事件唯一落库，重启不重复 |
| 图片404 | scene-evidence文件与eventId、备份完整性、查看权限 | 原事件图片能读；不能补实时图冒充 |
| 复核长期pending | VLM模型加载、平台登录、任务租约、worker超时、显存 | 对原eventId产生终态或明确失败码 |
| 门口无进入 | gate.enabled/verified、版本回读、线两侧、轨迹稳定性 | 真实外→内+1，内走/反向不加 |
| DeepSeek未配置/失败 | 配置状态、HTTPS地址、授权密钥、网络/超时 | 测试返回合法结果且不泄露密钥 |
| MES/EMS证据不足 | 定义、Tag绑定、历史权限和数据窗 | 有可追溯业务证据，禁止用演示数字填充 |

## 8. 测试与验收命令

在对应实际项目目录执行：

```powershell
Set-Location source\server
npm run build
npm run test:lint
npm test -- --exit
npx mocha test/api/sceneAnalysis*.test.js "test/cameras/scene*.test.js" --timeout 20000
Set-Location ..\client
npx tsc --noEmit -p src/tsconfig.app.json
npm run build -- --configuration production
Set-Location ..\..
python -m unittest discover -s source/tools -p test_scadia_scenes.py
```

实际服务联调（需本机9222测试浏览器和已配置工程登录；不输出口令/token）：

```powershell
Set-Location source
node tools/check-scenes-ui.mjs
node tools/check-scene-alarms-ui.mjs
node tools/check-scenes-consumers.mjs
```

最后一个命令会执行一次已授权DeepSeek分析并持久保存结果；不确认/清零现有事件、不修改订阅或外发邮件。结果写入artifacts/scenes-consumers-regression.json。通知发送用sceneConsumers测试中的本地桩；真实收件另行验收。更新SQLite内SVG脚本应先备份，再执行 `python source/tools/update-monitoring-project.py --ui-only` 并回读；该选项不重写tracker配置。部署用根目录deploy-scenes.ps1重启此工程进程，检查1881就绪与两源状态。

`npm test` 某些集成模块会留后台句柄，验收使用 `-- --exit` 明确结束；通过数与 pending 数分别记录。`verify_changes` 在默认工作区可能找不到此 D 盘工程，不能以 skipped 替代以上检查。

自动化测试覆盖协议、权限、状态机、持久化和部分竞态。现场必须另测门口真实通行、V2–T1阳性/混淆反例、画面尺寸和交互、真实报警确认、断网/重启、长时运行。已有66项页面矩阵是前一轮记录，本轮新增场景账本页面需独立现场可视验收，不把旧截图沿用为新页验收。

## 9. GitHub 发布与旧版本整理

当前源码目标为 `kcylp/SCADIA`。用户确认的清理范围是旧文档归档、保留 Git 历史和现场数据。旧 Release、标签和远程历史不做未经指定的删除，推送不使用强制覆盖。

发布前检查：

1. `git status` 和显式文件清单；不要直接把整个 project/runtime/models 加入暂存。
2. 逐文件审查代码和手册；检查链接、命令及已实现/待验收描述。
3. 扫描本地非默认敏感值是否进入候选文件；扫描只输出文件/行号，禁止打印值。
4. 运行测试并保存原始报告于本地 project/_logs；报告脱敏后才考虑提交。
5. 提交源码、文档、PLAN和验收记录，推送后核对远程 commit 和当前 README。

归档文档用于历史追溯，不是本版操作依据。此前远程历史可能包含现场运行材料；本轮不擅自重写历史。当前文件树的清理不会从 Git 历史中消除已经发布的内容。
