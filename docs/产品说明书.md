# SCADIA 产品说明书

适用：本仓库 2026-10-15 实现基线及其后本轮八场景接线修订。读者：项目负责人、实施人员、值班人员。当前操作以[使用手册](使用手册.md)为准，安装与备份以[部署维护手册](部署维护手册.md)为准。测试与现场待办分别查阅根目录 29_验收记录和 27_PLAN。

## 1. 产品定位与交付范围

SCADIA 是独立运行的工业监控工程，包含 Node.js 服务、Angular 客户端、HMI 工程、设备与采集集成、报警、视频、报表、脚本及 AI 证据分析。视频链路通过本地代理取帧，Python 检测服务生成轨迹和规则候选，本地 VLM 对事件证据或周期巡视进行复核。统一 AI 分析入口使用服务端筛选后的结构化证据。

本仓库交付源码、测试、启动/部署脚本与文档。现场工程数据库、相机密码、模型密钥、实际模型权重、Python 环境、Node 便携运行时、录像和抓拍不属于公开源码包。已经安装的工作站与 GitHub 新克隆的内容不同；后者需要按部署手册安装依赖并导入授权工程。

**当前阶段：具备运行链路与测试基线，仍有现场验收未完成项。不能据此声明八场景工业准确率验收通过。**

## 2. 系统组成

| 层 | 实际组成 | 职责 |
|---|---|---|
| 浏览器 | Angular 页面、统一分析 HTML | 显示画面、轨迹、候选、账本、复核与人工操作 |
| 平台服务 | source/server | 登录、权限、采集、存储、报警、场景账本、证据筛选、模型请求 |
| 视频代理 | source/tools/scadia-video-proxy.py | 获取视频源、缓存最新帧、提供本地快照 |
| 可见光检测 | scadia-ai-tracker.py + scadia_scenes.py | 人员跟踪、动作/视觉候选、方向规则、事件证据 |
| 红外检测 | 同一检测程序的独立配置/进程 | 独立红外源、独立轨迹与相对热源候选 |
| 本地复核 | scadia-scene-review.py | 单模型工作进程，事件任务优先并保留巡视轮询，失败诊断 |
| 证据分析 | api/analysis | 按模块、目标、时间窗和权限筛选证据后调用配置的 DeepSeek 服务 |

现场默认平台端口 1881，代理端口 1886；端口可依配置变化。9222 是已有开发调试端口，不是产品访问入口，也不是必需运行端口。

## 3. 八场景对应表

V1–V7 是共享可见光源上的七组业务规则，T1 是独立红外源。八个卡片不意味着八台独立摄像机。

| 编号 | 场景 | 主要依据与输出 | 现有边界 |
|---|---|---|---|
| V1 | 门口进入 | 指定门口 ROI、有限门槛线、室内侧、连续稳定轨迹；保存进入事件 | 过门后朝镜头或远处玻璃门走均计进入；实际现场坐标尚未完成标定与真实通行验收 |
| V2 | 跌倒复核 | 姿态/人体几何候选，提交事件级复核 | 缺现场跌倒阳性与弯腰等反例验收，候选不等于确认跌倒 |
| V3 | 抽烟复核 | 手口姿态等候选，结合抓拍/上下文复核 | 手靠近嘴不能独立证明抽烟；缺烟具、烟雾与动作专项验真 |
| V4 | 安全帽 | 独立安全帽检测配置及人头关联、缺少能力提示 | 未配置或权重未验真时应显示能力不足，不能声称已可靠识别 |
| V5 | 人员聚集 | 可见人员数量、持续时间及规则状态 | 受遮挡、跟踪漏检影响；候选阈值需现场设定和验证 |
| V6 | 禁区 / 滞留 | ROI、轨迹和持续观察时间 | 区域需现场配置；断流、离开画面不能累计为连续静止 |
| V7 | 烟火 / 通道 / 画质 | 颜色/烟火候选、指定区域、模糊/黑屏/冻结指标 | 小火苗专项模型、通道区域及阳性混淆样本仍待验收 |
| T1 | 红外辅助 | 独立红外渲染流上的相对热源异常候选 | 未接真实测温接口，无摄氏度、体温或诊断承诺 |

场景标识贯穿检测状态、事件行、逐事件复核、统一 AI 目标和历史图片。每条记录有 eventId、sceneId、camera、发生时间、类型、轨迹标识、规则版本，以及可选的复核与人工确认字段。新事件记录 source，旧事件按场景映射时注明 legacy_scene_mapping，不能把映射说成独立验真。

## 4. 门口进入判定

门口区域只包含指定门槛及两侧足够的稳定观察空间。判断锚点使用人员框底部中心。同一轨迹需要在门外稳定出现，穿过有限门槛线，再在室内侧稳定出现。正向成功仅计一次；离开区域、抖动、从端点绕行、长间断与短时丢失按状态机处理。

室内走动、工位停留、画面任意右移/左移、反向离开都不能简单计为进入。同一人重新回到门外并再次完成进入，可以产生新的通行次数。没有身份识别及完整出入口覆盖，不能把进入次数解释为唯一人数或室内总人数。

保存标定需要有效多边形、门槛端点、室内点、显式确认和配置版本检查。worker 成功构建新规则后才报告 appliedCalibrationVersion；保存成功与 worker 应用成功需要分别验证。未确认或未应用时不生成进入记录。

**截至基线验收，实际门位置仍未标定。方向口径已经记录，不等于几何标定完成。** 现场完成后应更新根目录 PLAN、版本回读和真实正反通行验收，而不能只改此文档中的状态。

## 5. 三种 AI 结果与人工确认

1. 检测候选：规则或检测器触发，是后续复核的输入。
2. 周期巡视：查看当前画面，界面标“巡视（非事件）”，不能替代事件账本。
3. 事件 VLM 复核：绑定 eventId 和历史证据，可输出“支持 / 不支持 / 证据不足”。
4. 人工确认：操作员确认已查看/处置对应事件，独立保存确认时间与身份。

reviewStatus 的 pending、running、completed、failed、timeout、unavailable 表示任务状态。completed 只说明任务完成，须同时阅读 verdict、text、limitations。模型 JSON 合法、HTTP 返回 200、生成速度快均不能证明事实正确。人工 ACK 也不自动证明模型判断正确或现场风险已解除。

统一 AI 支持八场景综合、V1–V7/T1、精确eventId及报表固定窗口；全窗总量、分组、趋势与最近30条明细由同次账本快照生成，明确总数与抽样截断，完整历史可分页或导出JSON。成功分析持久保存原问题、窗口、筛选、证据和回答，管理员可回读/导出原始记录。当前源健康状态作为 health 上下文展示，不因当前离线否定合法历史，也不以历史记录证明当前正常。

证据不足时，服务返回 evidence_insufficient 和缺失项；不会为填满界面编造事件。事件图片从指定 eventId 的历史文件读取，缺失返回不可用，不回退实时画面。历史与当前画面必须分别理解。

## 7. 数据与权限

场景事件 inbox 位于工作目录 scene-events，SQLite 持久账本由 SceneStore 管理；历史图片位于同一工作目录 scene-evidence，当前状态/轨迹位于工程 images 目录。工作目录通常是 project/_appdata，需以启动参数 --userDir 为准。

统计清零只影响统计投影，保留历史事件、图片和确认，不等于删除全部数据。备份需覆盖整个授权工程，而不只是单个数据库文件。事件会随着运行积累，需要站点制定存储容量和归档策略；当前不宣称有已经验收的长期自动清理机制。

安全模式开启时，全局八场景状态、画面、账本、历史证据和统一分析汇总需要管理员权限，原因是尚无逐相机 ACL。开放模式允许查看，但标定、清零、ACK 和模型配置仍要求经验证的管理员登录。实际网络开放范围由 settings.js 与防火墙共同决定。

## 8. 验收与交付判据

测试分为源码检查、接口/状态机测试、页面测试、现场语义验收及长期稳定性。每种通过仅覆盖各自范围。根目录 29_验收记录记录既有 66 页面检查和延迟采样；本轮新增接线验证记录见 docs/本轮验收记录.md。

现场还需闭环：门口几何标定与正反通行；八场景独立阳性/混淆样本；专项模型来源与适配；真实报警 ACK；MES/EMS 数据映射；30分钟/2小时稳定性与故障恢复。每项应记录设备、时间、规则/模型版本、输入证据、期望、实际、失败和复测，未完成不得勾选通过。

## 9. 已知限制与变更管理

- 相机安装角度、遮挡、低照度、红外渲染方式和压缩会影响识别。
- 改变相机角度、源分辨率或镜像设置后，应重做门口/禁区/通道标定及通行验证。
- 本轮没有取得相机曝光至屏幕呈现的完整时间链，不能将推理耗时当端到端延迟。
- 本地 VLM 可能发生截断、人数冲突、推理/CUDA 故障；失败诊断保留，重试成功不抹去历史失败。
- 本文不是准确率、连续可用率或安全等级认证。新增功能必须同步实现、测试、PLAN 和手册状态。
