## §1 环境与依赖

### 1.1 必需

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **>= 18**（实测 24.19 可跑；运行日志里会打印 `node.js version >=18` 检查，见 `server/main.js:355-356` 的 `unsupported_version` 分支） | 后端与前端构建共用 |
| npm | 随 Node | 依赖体积大，首次安装耗时长 |
| 原生编译工具链 | `sqlite3`、`serialport`、`node-opcua` 需要 | Windows 需 VS Build Tools；Linux 需 build-essential + python3 |

### 1.2 两处 node_modules（都要装）

```bash
cd 源代码/server && npm install     # 后端依赖（express/socket.io/sqlite3/node-opcua/serialport/mqtt/...）
cd ../client     && npm install     # 前端依赖（@angular/* + 20 余个 UI/图表库）
```

**【实测】** 两份 `node_modules` 当前都已存在；仓库根目录**没有** `node_modules`，根 `package.json` 不是构建入口。

## §2 构建与运行

### 2.1 最短路径

```bash
# 1) 构建前端（改过 client/src 就必须做；产物落到 client/dist，后端自动托管）
cd 源代码/client
npx ng build                       # 等价 npm run build

# 2) 起后端（工作目录必须是 server/，因为相对路径按它解析）
cd ../server
node main.js --port 1881 --userDir "<工程目录>"
```

- 浏览器打开 **http://127.0.0.1:1881/**
- `--userDir` 指向**工程目录**（内含 `_appdata/ _db/ _images/`）；**不传则默认用 `server/` 自己**，那样会污染源码目录。
- 端口来源优先级：命令行 `--port`（`server/main.js:335-336`）> `<userDir>/_appdata/mysettings.json` 的 `uiPort`（`server/main.js:146-148`）> 默认 **1881**（`server/main.js:338-339`）。

### 2.2 一键脚本（推荐给新同事）

仓库根 `start-scadia.ps1`：**它会做前置检查**（server 存在 / node_modules 存在 / client/dist 存在 / project 结构完整 / 端口空闲），并可选择构建前端。

| 参数 | 作用 |
|---|---|
| 无 | 用真实工程 `project/` 启动（服务端会写其中的 `_appdata`） |
| `-Sandbox` | 先把 `_appdata/_db/_images` 复制到临时目录再启动，**不动** `project/` |
| `-Rebuild` | 强制 `npx ng build` 后再启动 |
| `-Port 1882` | 换端口 |

> 脚本内部就是 `node main.js --port <Port> --userDir <runDir>`（`start-scadia.ps1:110-115`）。

### 2.3 前端多环境构建

`client/src/environments/` 有 4 套：`environment.ts`（默认）、`environment.prod.ts`、`environment.demo.ts`、`environment.client.ts`。
`angular.json` 里对应多套 configuration，`npm run build` 走默认；开发服务可 `npm run start` / `start:lan` / `demo` / `client`（`client/package.json` scripts）。

> **注意**：`ng serve` 起来的是前端开发服务器（默认 4200），它**不提供后端 API**；联调要么让后端托管 `client/dist`，要么自己配代理。

### 2.4 桌面外壳

```bash
cd 源代码/app/electron
npm install
npm start            # electron .
npm run dist         # electron-builder 打包
```

## §4 代码约定与不可破坏的兼容点

### 4.1 命名与目录约定

| 约定 | 含义 | 例子 |
|---|---|---|
| `_` 前缀目录 | **框架基础设施**，不是业务页面 | `client/src/app/_services/`、`_models/`、`_helpers/` |
| 后端 `runtime/<域>/index.js` | 一个域一个目录，导出 `init/start/stop` 风格的门面 | `runtime/devices/index.js` |
| 后端 `api/<域>/index.js` | 一个 REST 域一个目录，导出 `init()` 与 `app()` | `api/devices/index.js` |
| 驱动目录 | 每个协议一个目录，实现同一组函数 | `runtime/devices/modbus/` |
| 前端组件三件套 | `*.component.ts` + `.html` + `.scss`（部分老组件用 `.css`） | `gauges/controls/...` |
| 控件 `TypeTag` | 每种画面控件一个 `svg-ext-*` 字符串，是 SVG 元素与运行时的关联键 | `ValueComponent.TypeTag = 'svg-ext-value'` |

### 4.2 日志（后端）

- 用 **winston**，唯一实例在 `server/runtime/logger.js`。
- 输出文件：**`<userDir>/_logs/scadia.log`**（info 级，单文件 1 MB、最多 5 个轮转）与 **`scadia-err.log`**（错误）。
- 级别：`NODE_ENV=production` → `info`，否则 `debug`（`logger.js:24`）。
- **console 输出被注释掉了**（`logger.js:31-38`）——所以"屏幕上没打印"不等于"没发生"，**排障第一件事是看日志文件**。
- HTTP 访问日志另走 morgan：`api.log` + stderr/stdout 各一份（`main.js:489-507`）。

### 4.3 前后端接口约定（前端）

- **不要硬编码 API 地址**：统一用 `client/src/app/_helpers/endpointapi.ts` 的 `EndPointApi.getURL()`。
- 它会：优先 `environment.apiEndpoint` → 若由后端托管则用 `location.origin + getBasePath()`（`endpointapi.ts:21-40`）→ 否则用开发端口。
- `getBasePath()` 从 `<base href>` 推导，用于子路径部署（和后端 `BASE_PATH` 逻辑配对）。
- 该文件里留有一段血泪注释：**曾经无条件把端口改写成 `environment.apiPort`**，导致用 `--port 1900` 启动时页面能开、所有请求全失败（`endpointapi.ts:26-33`）。改动这段前先想清楚。

### 4.4 不可破坏的兼容点（改了就会静默坏）

| 兼容点 | 位置 | 为什么不能改 |
|---|---|---|
| LocalStorage 键 `@frango.*` | `client/src/app/editor/editor.component.ts:343-345`、`device/device.component.ts:54-57` | 老用户的前端偏好就存在这些键下；有测试守卫 |
| `@frango.webeditor.panelsState` | `editor.component.ts:1224,1239` | 编辑器面板布局状态 |
| 各域数据库文件名 `*.scadiap.db`，且**要兼容旧后缀 `.fuxap.db`** | `server/runtime/storage/databases.js:92`，测试 `test/storage/domainDatabaseFiles.test.js` | 现场已有数据文件 |
| `tagId`（GUID） | 全平台 | 历史/报警/标定都按 tagId 存，改了等于丢数据 |
| 画面 `items` 的 key 必须等于 SVG 元素 `id` | `server` 无关，纯前端：`gauges.component.ts:322` `document.getElementById(ga.id)` | 对不上就绑不上事件 |
| 内容词典必须覆盖全部已发布语言 | `client/src/app/_helpers/content-seed.ts` + `test/i18n/*` | 已有测试守卫 |
| i18n 文件**扁平点号 key 与嵌套对象混用** | `assets/i18n/*.json`，解析器 `_helpers/flat-translate.parser.ts` | 上游文件格式如此，两种写法都要能读 |

### 4.5 错误语义

`test/architecture/errorSemantics.test.js` 把"错误怎么表达"固化了。写新的后端接口时，遵循既有域的做法（返回结构化的 `{error, message}` 并同时写 `logger.error`，见 `api/projects/index.js:48-58`），不要自己发明。

## §5 扩展指南（常见开发任务）

> 每一条都按 **"改哪些文件 → 顺序 → 怎么验证"** 写。漏掉的注册点会让功能"看起来写好了但不生效"，这是本项目最容易犯的错。

### 5.1 新增一个设备协议驱动

1. **抄模板**：复制 `server/runtime/devices/template/` 为新目录，例如 `myproto/`。模板里实现了驱动要暴露的一组函数（`init/create` 与 `load/connect/getValues/setValue/getTagProperty`，见 `runtime/devices/device.js` 的统一外壳）。
2. **接线**：设备外壳按 `device.type` 派发到具体驱动（`server/runtime/devices/device.js`），把新类型加进去。
3. **设备类型枚举**：后端 `runtime/devices/index.js` 与前端 `client/src/app/_models/device.ts` 的 `DeviceType` **两处都要加**。
4. **前端标签编辑对话框**：设备页按类型打开不同的标签属性对话框（`client/src/app/device/device-tag-*/...`），新协议要提供一个（可先复用最接近的）。
5. **命名约定**：驱动目录名即 `DeviceType` 的小写（对照现有 17 个驱动）。
6. **验证**：
   - 单元测试参考 `server/test/devices/modbusDatatypes.test.js`、`httprequest.test.js`、`websocket.test.js` 的写法；
   - 跑 `npm run test:gate`（含 `brandingGuard`，防止把上游品牌串带进来）。

### 5.2 新增一个画面控件

1. **新建组件**：`client/src/app/gauges/controls/<name>/<name>.component.ts`，继承 `GaugeBaseComponent`，定义
   - `static TypeTag = 'svg-ext-<name>'`（**这是 SVG 元素与运行时关联的键，必须唯一**）
   - `static LabelTag`、`static getSignals/getActions/getDialogType`，需要处理数据时实现 `static processValue(...)`。
2. **注册**：把组件类加进 **`client/src/app/gauges/gauges.component.ts:81` 的 `static Gauges = [...]`**。漏了这一步 = 控件不可用（`:113-115` 会据此生成 `gaugesTags`）。
3. **绑定位**：若控件不是"HTML 浮层"而是直接改 SVG 元素，还需要在 `gauges.component.ts` 的 `initInEditor()`（`:204-253`）或 `initElementAdded` 分支里处理（参考 `ValueComponent` 的 `g.textContent = val`）。
4. **编辑器工具箱**：在 `client/src/app/editor/editor.component.html` 的"控制"面板加一个按钮，用 `setMode('<mode>')`，并补 i18n 词条 `editor.controls-<name>`。
5. **属性对话框**：控件若有专属属性，走 `GaugeDialogType`（`gauges/gauge-property/gauge-property.component.ts`）分发；简单控件复用现有对话框即可。
6. **验证**：在编辑器里摆放 → 绑定变量 → `/home` 看是否随值变化；事件类控件在 `/home` 点击验证（注意 §7 的 `/view` 差异）。

### 5.3 新增一个 REST 接口

1. **建域**：`server/api/<域>/index.js`，导出 `init(runtime, secureFnc, checkGroupsFnc)` 与 `app()`，在 `app()` 里 `prjApp.get/post(...)`（照抄 `api/projects/index.js`）。
2. **注册**：在 `server/api/index.js` 里挂上（`app.use(...)`）。
3. **鉴权**：路由第二个参数传 `secureFnc`；需要管理员权限时用 `authJwt.haveAdminPermission(permission)`（`api/jwt-helper.js`）。
4. **错误语义**：遵循 `api/projects/index.js:48-58` 的 `{error, message}` + `logger.error` 写法（有测试守卫 `test/architecture/errorSemantics.test.js`）。
5. **文档**：更新 `server/docs/openapi.yaml`。
6. **前端调用**：走 `_services/*.ts` + `EndPointApi.getURL()`，不要硬编码地址。
7. **验证**：`curl` 或 `Invoke-WebRequest` 直打接口；安全相关改动补一条 `test/authorization/*` 用例（照抄 `pathNormalizationSecurity.test.js`）。

### 5.4 新增一条前端路由 / 页面（★ 最容易踩的坑）

**必须同时改两处，少一处就会出现"应用内能点、刷新就白屏"**：

1. `client/src/app/app.routing.ts` 加路由（`{ path: 'xxx', component: XxxComponent, canActivate: [AuthGuard] }`）。
2. **`server/main.js:446-462` 的 `SHELL_ROUTES` 加上 `'/xxx'`** —— 这张表是**唯一**会把客户端路由回以 `index.html` 的地方；不在表里 → 直接访问/刷新返回 **404**，浏览器白屏（已在核查报告 P0-1 复现）。表的位置在 `server/main.js:446-481`。
3. 组件要写进 `client/src/app/app.module.ts` 的 `declarations`（本项目未用 standalone 组件）。
4. 若要从左侧菜单进入，还要加到 `client/src/app/_models/default-navigation.ts` 的 `DEFAULT_NAVIGATION`（路由用 `page(id, 文案key, 图标, 路由名)`），并在 `assets/i18n/*.json` 补 `nav.*` 词条。
5. **验证**：应用内点击 → 正常；**再直接刷新该 URL** → 仍正常（这一步才是真验证）；最后 `ng build` 并重启后端。

### 5.5 新增/修改语言与词条

- **已发布语言**只有 `zh-cn/en/ru`，清单硬编码在 `client/src/app/_models/settings.ts:11` `SHIPPED_APP_LANGUAGES`（配套 `SHIPPED_APP_LANGUAGE_NAMES`、`SHIPPED_LOCALE_FORMATS` 管日期/小数分隔符）。
- **新增语言** = 加 `assets/i18n/<lang>.json` **并**把该语言加进上面三个常量；否则加载器会去请求不存在的文件，ngx-translate 会把**原始 key 直接显示在界面上**（`settings.ts:1-10` 的注释就是为此写的）。
- **i18n 文件格式是"扁平点号 key + 嵌套对象"混用**，解析器在 `_helpers/flat-translate.parser.ts`；两种写法都要能读。
- **画面里的中文**不走 i18n key，走**内容词典**：`_helpers/content-seed.ts` 按"原文 → 各语言"登记，运行时由 `scadia-view.component.ts` 的 `applyContentDictionary()` 逐 `<text>/<tspan>/<title>` 替换。新增词条必须**带全部已发布语言**，否则 `test/i18n/i18nCoverage.test.js` 会失败。
- 运行面模板里显示项目内容要用 `| contentText` 管道（`_helpers/content-text.pipe.ts`），`test/i18n/contentWiring.test.js` 会检查。
- **注意**：`applyContentDictionary` 会**跳过**那些"已被变量写入"的 `<text>`（`scadia-view.component.ts:145-146` 判断 `view.items[id].property.variableId`），以免把实时值翻译掉——这是设计，不要"修"。

### 5.6 新增画面图元（形状/符号）

1. 在 `client/src/assets/lib/svgeditor/shapes/` 下新增/修改 `*.js`：每个图元是 `{ name, ico, content: [{ type:'path'|'rect'|..., attr:{...} }] }`，末尾把数组塞进 `svgEditor.shapesGrps[shapesGroupName]`（照抄 `my-shapes.js`）。
2. **注册加载**：`shapes/shapes.js:11` 的 `shapesToLoad` 数组——**只有列在这里的文件才会被加载**。
   - 本项目只加载 `my-shapes.js`（图形，39 个）、`proc-shapes.js`（Proc. Eng.，112 个工业 P&ID 符号）、`ape-shapes.js`（动画，2 个）。
   - 磁盘上存在的 `proc-general-shapes.js` / `proc-pumps-shapes.js` / `proc-comp-shapes.js` **没有被加载**（死文件），别以为改了它们会生效。
3. 分组名就是编辑器左侧面板的标题，走 i18n（如 `editor.shape`、`editor.processeng`、`editor.animated`）。
4. **验证**：重新 `ng build` → 刷新编辑器 → 左侧出现新图元 → 拖到画布。

### 5.7 修改工程数据模型（增字段 / 增命令）

工程数据落在 SQLite 的段表里（`views/devices/alarms/...`，每行一个 JSON），**没有 ORM、没有迁移框架**：

1. **命令类型两处同步**：客户端 `client/src/app/_models/project.ts:54` `enum ProjectDataCmdType` 与 服务端 `server/runtime/project/index.js:1302` 的同名对象——**必须一致**（服务端 `:217-220` 按命令分派）。
2. **加载/保存**：`runtime/project/index.js` 的 `load()`（`:59-` 区段，逐表读入 `data`）与保存侧 `:842-` 区段（把内存写回表）。
3. **向后兼容**：老工程里没有新字段是常态——读取处必须容错（本项目为此踩过坑，见 §7）。
4. **注意 `general` 表的特殊行**：`layout` 一行存的是整个 `LayoutSettings` JSON；**写入时必须带全 `navigation` 与 `header`**，否则 `runtime/project/index.js:1184/1193` 会抛异常导致 `/api/project` 失败（核查报告 P0-2）。
5. **验证**：改完重启后端（工程数据是启动时读进内存的），确认 `/api/project` 200，再在编辑器里改一次并保存，确认落库。

### 5.8 新增历史库（DAQ）后端

1. 在 `server/runtime/storage/` 下按现有后端实现同一组接口（`server/runtime/storage/contract.js` 定义了契约）。
2. 在 `server/runtime/storage/registry.js` 注册，`databases.js` 管库文件命名（`:92` 有旧后缀兼容逻辑）。

### 6.3 画面/组态的无头验证（本项目实践，建议固化成回归脚本）

对 UI 类改动（画面、缩放、导航），人工点很容易漏。可复用的方法是 **headless Chrome + CDP**：

1. 起一个带调试端口的 Chrome：
   ```
   chrome.exe --headless=new --disable-gpu --no-sandbox --remote-debugging-port=9333 --user-data-dir=%TEMP%\cdp about:blank
   ```
2. 用 Node 连 CDP（`http://127.0.0.1:9333/json/list` 拿 `webSocketDebuggerUrl`，Node 18+ 自带 WebSocket）：
   - `Page.navigate` 打开页面；
   - `Runtime.evaluate` 读 DOM（画面标题、控件 id、可见文本长度）；
   - `Emulation.setDeviceMetricsOverride` 换分辨率，验证缩放；
   - `Input.dispatchMouseEvent` 发真实点击，验证交互（比 `element.click()` 可信，会走命中测试）；
   - `Page.captureScreenshot` 截图后交视觉模型复核"有没有黑边/错位"。
3. 断言样例：切换左列导航后 `document.querySelector('#content svg title').textContent` 应变为目标画面名。

> 这套方法在本次核查中直接抓出了三个真实缺陷（白屏、缩放错位、导航不生效），比读代码快。

## §7 血泪清单（本项目实际踩过的坑）

> 这一节全是**已经发生过的真实故障**（标【实测】的都在运行实例上复现过）或**已核对源码的结构性隐患**。
> 每条给：现象 → 根因 → 证据 → 教训（改代码前先读）。

### 7.1 一改就坏型（改代码必看）

| # | 现象 | 根因 | 证据 | 教训 |
|---|---|---|---|---|
| 1 | 应用内点得进去，**一刷新就 404 白屏**（`document.querySelector('app-root')` 为 null） | 服务端 `SHELL_ROUTES` 与前端 `app.routing.ts` **手工维护的两张表不同步**；不在表里的客户端路由不会被回以 `index.html` | 【实测】`server/main.js:446-481`；原始版本只有 15 条，`/alarms /messages /notifications /scripts /recipes /reports /language /logs /events /mapsLocations /flows /apikeys /userRoles /arMarkers` 共 14 条直接访问 404；**无任何测试守卫** | 新增路由**必须两处都改**（见 §5.4），并且要**直接刷新 URL** 才算验证过 |
| 2 | 打开系统**整站空画布**，后端日志 `api get project: TypeError: Cannot read properties of undefined (reading 'items')` | 工程 `general.layout` 行写成了 `"start":"v_zc_g1"` 这种残缺 JSON，而读取处**只判 `layout` 存在、不判 `layout.navigation`/`layout.header`** | 【实测】`server/runtime/project/index.js:1184`（取 `layout.navigation.items`）、`:1193`（取 `layout.header.items`）；修复前 `/api/project?views=lazy` 直接 4xx | 写 `layout` 必须带全 `navigation` 与 `header` 默认对象；读取处要可选链（核查报告 P0-2） |
| 3 | 同一工程，`/home` 时钟走秒，**`/view?name=AI检测`（大屏）时钟不动** | 定时客户端脚本的调度只写在首页：`mode===CLIENT && scheduling.interval>0` 才 `setInterval` | 【实测】`client/src/app/home/home.component.ts:185-197` 的 `initScheduledScripts()`；`view/view.component.ts` **没有任何等价逻辑** | 运行面能力（脚本调度、事件处理、缩放）**要么抽公共、要么两个入口都接**；改运行面行为要**在两条路由上各验一次** |
| 4 | `/view` 与 `/home` **能力不对等**（不止脚本：导航/页眉/事件处理路径也不同） | `/view` 是给大屏/展示用的独立路由，只做了渲染，没接 `home` 的运行逻辑 | `client/src/app/app.component.ts:180` 对 `/view` 隐藏开发导航；`home.component.ts:597-614` 处理 `onpage` 跳转 | 把"能渲染"当成"能用"是错的；大屏交付前必须按 §6.3 无头验证 |
| 5 | 编辑器里改了命令/字段，**保存静默失败**（无报错、不落库） | 命令枚举**前后端两张手工表**，无生成、无校验、无测试 | 客户端 `client/src/app/_models/project.ts:54` 的 `enum ProjectDataCmdType`；服务端 `server/runtime/project/index.js:1302` 的 `const ProjectDataCmdType = {}`（分派在 `:217-220`） | 增命令**必须两处同步**（§5.7）；漏一侧不报错，只静默丢数据 |
| 6 | （隐患）服务端命令表里有**重复键** | `SetText: 'set-text'` **连续写了两次**，复制粘贴残留；因为值相同所以功能无影响 | `server/runtime/project/index.js:1312-1313` | 重复键本身说明**这张表是手抄的**——没有生成机制就没有单一事实源，长期必然漂移（核查报告 P2） |
| 7 | 改了形状文件却**在编辑器里看不到新图元** | 形状文件是"按名单加载"的，磁盘上有文件 ≠ 被加载 | `client/src/assets/lib/svgeditor/shapes/shapes.js:11` 的 `shapesToLoad = ['my-shapes.js','proc-shapes.js','ape-shapes.js']`；磁盘上还有 **3 个死文件**（`proc-general-shapes.js`/`proc-pumps-shapes.js`/`proc-comp-shapes.js`） | 加图元=改文件**并**进加载表（§5.6）；先怀疑"没加载"，再怀疑自己写错了 |
| 8 | （隐患）给非管理员配了权限后，画面 **SVG 结构被破坏/渲染错乱** | 权限过滤**不改数据模型**，而是拿"id 在 SVG 字符串里第一次出现的位置 + id 长度 + 1"**往 SVG 源码里插 visibility 属性** | `server/runtime/project/index.js:1202-1223`：`var position = view.svgcontent.indexOf(item.id); position += item.id.length + 1; ... slice(0,position) + hidetext + slice(position)` | `indexOf` 只找第一次出现（id 若先出现在 title/注释/别的引用里，插入点就错位）；`+1` 假定 id 后紧跟一个字符。**应按正则定位 id="<id>" 的完整属性，或在模型层加 hidden 字段由前端渲染**（核查报告 P1） |
| 9 | 用非默认端口启动后，**页面能开、所有请求全失败** | 前端曾在"由服务端托管"的分支里**无条件把端口改写成 environment.apiPort（1881）**，没判断页面到底从哪来 | 代码内注释原文见 `client/src/app/_helpers/endpointapi.ts:29-33`（用 `--port 1900` 起服务 → UI 去调 1900 主机的 1881）；现在改为 `location.origin + getBasePath()`（`:34`） | 前端**永远不要硬编码端口**；一律走 `EndPointApi.getURL()`；改部署方式时要按"IP 访问 / 域名访问 / 子路径 / 换端口"四种各验一次 |
| 10 | 直接改工程库 `*.db` 后**改动被覆盖或服务读到旧值** | 工程数据**不是代码**：启动时一次性读进内存（`runtime/project/index.js` 的 `load()`），运行期以内存为准 | `runtime/project/index.js:59-` 读入 / `:842-` 写回；`prjstorage.js` 只管表 | **改库先停服务、改完再起**；生产上改库前必须备份 `_appdata` |
