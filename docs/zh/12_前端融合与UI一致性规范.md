# 12 前端融合与 UI 一致性规范（目标："看着就是一个开发者做的"）

> 委托方要求：**任何新融合进来的东西（机器人地图 / MES / EMS / 视频 / AI），前端必须与现有界面毫无违和，
> 配色、排版、交互一致；同时"进去的时候可以有不同的开发入口"。**
> 本文件把这件"感觉上的事"变成**可核对的规则 + 可抄的模板 + 可验收的清单**，全部基于 `源代码/client` 的实测事实。

---

## 0. 一句话结论

这套前端的"设计基因"是 **Angular Material 18 + 一套 CSS 变量主题（浅色/深色双主题，品牌主色 `#3059af`）**。
所以"毫无违和"的技术定义只有一条：

> **新页面不得自带设计系统。** 颜色只能来自 `var(--*)`，组件只能用 Angular Material + 现有 `gui-helpers`，
> 文案只能来自 i18n key，图标只能用 `material-icons` 的名字。

违反其中任何一条，界面就会立刻"看起来像另一个团队做的"——这不是审美问题，是**可核对的工程问题**。

## 1. 现状：这套前端的设计基因（实测）

### 1.1 技术底座

| 项 | 事实 | 证据 |
|---|---|---|
| 框架 | **Angular 18.2.14**（组件**非 standalone**，要进 `declarations`） | `client/package.json` |
| UI 库 | **`@angular/material` 18.2.14` + `@angular/cdk` 18.2.14`** | 同上 |
| 图标 | **`material-icons`**（用图标名字符串，如 `'dashboard'`、`'visibility'`） | `default-navigation.ts:52-91` |
| 通知 | **`ngx-toastr`**（还有本项目的 `_services/toast-notifier.service.ts` 封装） | `client/package.json`、`client/src/app/_services/` |
| 图表 | `chart.js 3.9 + ng2-charts + ngx-uplot（gui-helpers）` | 同上 |
| 地图 | **`leaflet 1.9.4`**（现有 `maps-view` 就用它） | `client/src/app/maps/maps-view/maps-view.component.ts:2` |
| 代码编辑 | `codemirror 5`（脚本页在用） | `client/package.json` |
| 其他 | ngx-color-picker、angular-gridster2、angular2-draggable、file-saver、html5-qrcode | 同上 |
| i18n | **`@ngx-translate/core` 14** + `assets/i18n/{zh-cn,en,ru}.json` | `_models/settings.ts:11` |

### 1.2 主题：**CSS 变量 + 双主题**（这是"一致"的关键机制）

- 主题定义在 `client/src/app/_config/theme.config.ts`：`THEMES.default`（浅色）与 `THEMES.dark`（深色），**每个主题 ~45 个 token**（header/toolbox/sidenav/form/scrollbar/chips/workPanel/mapBorder…）。
- 运行时由 `client/src/app/_services/theme.service.ts:13-28` 把 token 逐个写成 `document.documentElement.style.setProperty('--' + key, value)`，并给 `body` 加/去 `dark-theme` 类。
- **品牌主色（选中态）= `#3059af`**：`toolboxItemActiveBackground` / `chipSelectedBackground`（两个主题一致）。
- 深色主题的骨架色：工具栏/侧栏 `#252526`、面板 `#424242`、控件底 `#37373D`、焦点边框 `#1177BB`；浅色主题：侧栏 `#f9f9f9`、控件底 `#f1f3f4`、面板 `#FFFFFF`。
- 全局样式：`client/src/styles.css`（30.3 KB）、`client/src/scada.css`（13.9 KB）、`client/src/theme.scss`（7.7 KB）、`client/src/material-overrides.scss`（4.0 KB，**用来统一 Material 组件外观**）。

> **推论（必须遵守）**：新页面写 `color: #1890ff` 这类硬编码色 → 深色主题下必然"发光"；
> 写 `background: #fff` → 深色下必然刺眼。**这两条是外部系统接进来后最常见的违和来源。**

### 1.3 页面骨架与导航（现有 7 组、29 条路由）

- 路由表 `client/src/app/app.routing.ts`（29 条，含 `''`/`home`/`home/:viewName`/`view`/`ar` 无守卫，其余 `canActivate: [AuthGuard]`）。
- 左侧菜单是**声明式的一张三（类）型表**：`client/src/app/_models/default-navigation.ts`
  - `page(id, 'nav.xxx', 'material_icon', 'route')` —— 跳到应用路由；
  - `screen(...)` —— 跳到**工程画面**（只有工程里存在时才出现）；
  - `group(id, 'nav.group-xxx', icon, children)` —— 可展开的分组（自身不是目的地）。
- 现有 7 个分组（**新入口应当挂在已有分组里，而不是新造一套菜单**）：
  `overview`（首页/画面）、`monitor`（视频/报警）、`data`（报警历史/报表/配方）、`asset`（设备/相机/位置/标定）、`automation`（脚本/流程/通知）、`system`（用户/角色/语言/插件/密钥/日志/AR 标记）、**`engineering`（编辑器 / lab 实验室）**。

### 1.4 可复用组件（**不要自造**）

`client/src/app/gui-helpers/` 下 17 个现成件：`confirm-dialog`、`daterange-dialog`、`daterangepicker`、`edit-name`、`edit-placeholder`、`fab-button`、`mat-select-search`、`ngx-gauge`、`ngx-nouislider`、`ngx-scheduler`、`ngx-switch`、`ngx-uplot`、`range-number`、`sel-options`、`treetable`、`webcam-player`、`bitmask`；另有 `client/src/app/paginator/`（分页）、`_services/toast-notifier.service.ts`（提示）。

### 1.5 文案与多语言（两套机制，别混）

| 机制 | 用于 | 规则 |
|---|---|---|
| **i18n key**（`assets/i18n/*.json` + `ngx-translate`） | 界面文字（菜单/按钮/表头/提示） | **三语言 `zh-cn/en/ru` 必须齐全**；语言清单硬编码在 `_models/settings.ts:11` 的 `SHIPPED_APP_LANGUAGES`（配套名称与日期格式两个常量） |
| **内容词典**（`_helpers/content-seed.ts`） | **画面里的中文**（SVG 文本） | 每条必须带**全部已发布语言**，否则 `test/i18n/i18nCoverage.test.js` 失败；运行时由 `scadia-view.component.ts:130-161` 替换，且**跳过被变量写入的 text**（`:145-146`，这是设计） |

> **直接后果**：新页面里写死一句中文 = 切到英文界面时它是中文；这是"不像同一个开发者"的第二大来源。

## 2. 六条一致性硬规则（可核对）

| # | 规则 | 违反后的症状 | 检查方法 |
|---|---|---|---|
| **R1 颜色** | 只能用 `var(--token)`；**新增语义色必须先加进 `theme.config.ts` 的 default 与 dark 两个主题** | 深色主题下颜色刺眼/看不见 | 全库 grep 新文件里的 `#[0-9a-fA-F]{3,6}` 与 `rgb(` |
| **R2 组件** | 只用 Angular Material + `gui-helpers`；**禁止引入 Element UI / Ant Design / Bootstrap 等第二套设计系统** | 输入框、按钮、弹窗风格明显不同 | 看 `package.json` 有没有新 UI 依赖 |
| **R3 图标** | 只用 `material-icons` 的名字（与 `default-navigation` 一致） | 图标线条/圆角/风格不一致 | 看模板里有没有 `<img src…icon>` 或 SVG 图标集 |
| **R4 文案** | 全部走 i18n key，新增 `nav.*`/页面 key 时**三语言一起加** | 切语言出现 key 或中文残留 | 跑 `npm run test:gate`（含 i18n 守卫） |
| **R5 交互** | 确认用 `confirm-dialog`；提示用 `ngx-toastr`/`toast-notifier`；**禁止 `alert()`/`window.confirm()`/裸 `console.error` 当提示** | 弹窗风格突变、错误只出现在控制台 | grep 新代码 |
| **R6 路由** | 新页面必须**四处同步**：`app.routing.ts` + `server/main.js` 的 `SHELL_ROUTES` + `app.module.ts` 的 `declarations` + `default-navigation.ts`（含 `nav.*` 词条） | **应用内能点、刷新即 404 白屏**（本项目的 P0-1） | 直接刷新 URL 必须 200 |

## 3. 五种"入口"（委托方要的"不同的开发入口"）

现有应用已经天然分了三层，**新模块按用途分别挂，不要每个模块都造一个菜单**：

| 入口 | 面向谁 | 挂在哪（现状） | 新模块该放什么 |
|---|---|---|---|
| **E1 运行面** | 操作员 | `/home`（起始画面）、`/view?name=…`（大屏，`app.component.ts:180` 对它隐藏开发导航）、`?kiosk=1` | 只放"能操作/必须看"的东西（机器人地图控件、能耗看板画面） |
| **E2 管理面** | 值班/管理员 | 左侧导航常规分组（monitor/data/asset/system） | 台账、报警规则、报表、用户可见的列表页 |
| **E3 工程面** | 开发者/调试者 | **`g-engineering` 组：`/editor` 与 `/lab`** | **配置、诊断、调试、模拟数据入口放这里**（委托方要的"开发入口"就是这一层） |
| **E4 画面内嵌** | 组态工程师 | 编辑器工具箱（`editor.component.html:135-217` 的"控制"面板）+ 控件注册表 `gauges.component.ts:81` | 新控件（如 `svg-ext-robot-map`）在工具箱里出现，属性对话框走 `gauge-property` |

## 4. 新页面模板（照着抄，8 个改动点）

`
1) 目录      client/src/app/<domain>/<page>/<page>.component.{ts,html,scss}
2) 组件      @Component({selector:'app-<page>', templateUrl, styleUrls})  ← 非 standalone
3) 声明      client/src/app/app.module.ts → declarations
4) 路由      client/src/app/app.routing.ts → { path:'<route>', component: X, canActivate:[AuthGuard] }
5) 白屏防护  server/main.js:446-481 的 SHELL_ROUTES → 加上 '/<route>'     ★ 最容易漏
6) 菜单      client/src/app/_models/default-navigation.ts → 在合适的 group 里 page('n-xxx','nav.xxx','<material_icon>','<route>')
7) 文案      client/src/assets/i18n/{zh-cn,en,ru}.json → nav.xxx 与页面词条（三语言一起加）
8) 样式      <page>.component.scss 只写布局与间距；颜色一律 var(--token)
`

**页面内部的三条惯例**（与现有页面保持一致）：
- 列表页：工具条（搜索/新增）→ 表格/树表（`treetable`）→ 分页（`paginator`）；
- 表单：Material 表单控件 + `mat-select-search`（长下拉）+ `daterangepicker`（时间）；
- 反馈：成功/失败一律 `toast-notifier`；危险操作先 `confirm-dialog`。

## 5. "看起来不像同一个人做的"——典型症状自查表

| 症状 | 为什么会这样 | 修法 |
|---|---|---|
| 页面上出现第二套输入框/按钮样式 | 引入了 Element UI / Ant Design / Bootstrap 等 | 换回 Material（R2） |
| 深色主题下某块是白的、或字看不见 | 硬编码 `#fff`/`#000`/十六进制品牌色 | 改成 `var(--token)`；新色先进 `theme.config.ts`（R1） |
| 图标风格不一致（实心/描边/彩色） | 自带图标集或用了图片图标 | 换 `material-icons`（R3） |
| 切英文后仍有中文 | 文案写死，没走 i18n key | 抽 key + 三语言（R4） |
| 弹窗是浏览器原生样式 | 用了 `alert/confirm` | `confirm-dialog`/`toast-notifier`（R5） |
| 刷新页面 404 白屏 | 漏了 `SHELL_ROUTES` | 补齐并**直接刷新验证**（R6 / P0-1） |
| 表格行高、圆角、间距与别处不同 | 自己写了表格样式 | 复用现有页面结构/类名 |
| 进入方式像"外挂" | 新造了一套菜单分组 | 挂进已有 7 个分组（§1.3） |

## 6. 外部平台（MES / EMS / 视频）的"外壳"策略

这三个是**自带前端的完整系统**，无法用 Angular 组件级融合。三种做法，**必须明确选一种并写进交付说明**：

| 方案 | 一致性 | 成本 | 适用 | 违和程度 |
|---|---|---|---|---|
| **① 原生重做**（只用它的 API，界面全部用本系统组件重写） | ★★★★★ | 高 | 只做"十几个关键页面"的子集 | 无违和（**推荐用于 E1/E2**） |
| **② iframe 套壳**（本系统的 header/侧栏保持，内容区嵌它的页面） | ★★ | 低 | 需要用它完整功能、且用户能接受 | **必然有两套 UI**——只能"减少"不能"消除" |
| **③ 入口 + 指标回填**（只把外部系统的少量数字/状态拉回来，用本系统组件呈现） | ★★★★★ | 中低 | 管理看板、大屏 | 无违和（**推荐用于 E5 的降级形态**） |

若必须用 **②**，用这 5 条把违和压到最低（**做不到就别用 iframe**）：
1. **主题对齐**：把外部系统的主题色/背景改成与本系统 token 同值（它是 Vue/Element 时改它的主题变量，不是改它的代码结构）；
2. **只嵌内容区**：绝不让它再出现第二套顶部栏/侧边栏（给它一个"无壳"入口 URL，若它没有就自己加一个）；
3. **统一字体**：`font-family` 与 `--*` 变量对齐，避免字体突变；
4. **入口说明**：进入前给一行字说明"这是 XX 系统"，把"违和"变成"有意为之"；
5. **权限一致**：外部系统的账号/角色与本系统做映射（用户不该被要求再登录一次——否则体验割裂最明显）。

## 7. 验收清单（人工 + 可脚本化）

- [ ] **双主题截图对比**：新页面在 `default` 与 `dark` 下都截一张，与既有页面（如 `/recipes` 或 `/alarms`）并排看——**"像不像同一个人做的"就是这一步判定**。
- [ ] **直接刷新每个新路由**：必须 200 且不是白屏（R6 / P0-1）。
- [ ] **三语言切换**：切到 `en`/`ru` 无 key 泄漏、无中文残留（R4）。
- [ ] **深色下的状态色**：警告/错误/成功色在两个主题下都合法（不许出现白底白字）。
- [ ] **加载态与空态**：列表为空、接口失败时，界面有明确提示（走 toast），不是空白。
- [ ] **无第二套设计系统**：`client/package.json` 的 diff 里不应出现新的 UI 框架。
- [ ] **无硬编码颜色**：对新目录 grep `#[0-9a-fA-F]{6}` 应为 0（或每条都有注释说明为何例外）。
- [ ] **键盘与焦点**：Tab 能走通表单（Material 默认满足，自造控件容易破坏）。
- [ ] **与既有导航的关系**：新入口挂在已有分组下，没有新造顶级分组（除非有充分理由）。
