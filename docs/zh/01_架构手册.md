## §1 系统定位、血缘与版本

### 1.1 这是什么

一套 **Web 组态 SCADA/HMI 平台**：浏览器里完成"组态（画画面、建设备、绑变量）"和"运行（看画面、看实时数据、下命令）"两件事。工程数据与平台代码分离——**平台是程序，工程是数据**（工程 = `<userDir>/_appdata/*.db`）。

### 1.2 技术栈（实测）

| 层 | 技术 | 证据 |
|---|---|---|
| 前端 | **Angular 18.2.14**（TypeScript）+ Angular Material + RxJS + socket.io-client | `client/package.json`；运行页 console 打印 `Angular is running in development mode`、`SCADIA v1.0.0` |
| 画面渲染 | **vendored 的 svg-edit（jQuery 时代产物）**，非 Angular 原生 | `client/src/assets/lib/svgeditor/scadia-editor.min.js`（286 KB，内部版本串 `editor v2.9.12-173`） |
| 后端 | Node.js + Express + Socket.IO + sqlite3/node-opcua/serialport/mqtt… | `server/package.json` |
| 外壳 | Electron（桌面）/ headless 入口 | `app/electron/main.js`、`app/headless/headless-entry.js` |
| 工程库 | SQLite（`*.scadiap.db`） | `server/runtime/project/prjstorage.js:83` 等 |
| 历史库 | SQLite / InfluxDB / QuestDB / TDengine / PostgreSQL（五后端） | `server/runtime/storage/*` |

### 1.3 血缘与许可（重要，且与现有文档不符）

- **许可：MIT**，版权头为 **frangoteam**（`LICENSE:1-3`：`Copyright (c) 2019-2025 frangoteam info@frangoteam.org`）。二次开发**必须保留**该版权头。
- **真实上游是 FUXA（frangoteam）**，不是文档里写的 `github.com/kcylp/SCADIA`。证据：
  - `server/test/devices/brandingGuard.test.js:103` 把 `powered by frango` 记为 *"the very first upstream author"*；
  - 同文件 `:111-115` 把 `/fuxa/i` 记为 *"a previous product name"*，并要求产品对外只能是 Kaicheng；
  - `server/runtime/storage/databases.js:92` 仍兼容上一代产品的文件名后缀 `.fuxap.db` → `.scadiap.db`。
- **不可改的兼容点**：浏览器 LocalStorage 键仍为 `@frango.*`（`client/src/app/editor/editor.component.ts:343-345`、`client/src/app/device/device.component.ts:54-57`），改名会让老用户的前端偏好丢失。这一条已被 `brandingGuard.test.js` 固化为测试。

### 2.4 目录/参数解析要点

- `--userDir` → `rootDir`，`workDir = <rootDir>/_appdata`（`server/main.js:105-115` 区段）。
- 静态前端目录：优先 `../client/dist`，不存在则退到 `./dist`（`server/main.js:295-298`）。
- `BASE_PATH` 非空时会把 `<base href>` 与资源路径重写为子路径部署（`server/main.js:302-333`）；**注意**：只有 `BASE_PATH` 非空时才会注册逐路由的 index.html 处理器，否则 SPA 回退依赖 `express.static` 挂载表（这就是 §4 里那个白屏缺陷的成因）。

## §3 后端运行时架构

### 3.1 启动链路

```
node main.js [--port N] [--userDir DIR]
  ├─ 解析 CLI（main.js:30-52）
  ├─ 加载设置：settings.default.js → <userDir>/_appdata/settings.js → <userDir>/_appdata/mysettings.json 覆盖（main.js:95-154）
  ├─ 解析目录：rootDir=userDir、workDir=<rootDir>/_appdata、_images/_widgets/_reports/_logs/_db（main.js:101-115）
  ├─ 检查 Node 版本（main.js:355-356 的 unsupported_version 分支）
  ├─ 解析静态前端目录：../client/dist 否则 ./dist（main.js:295-298）
  ├─ 注册中间件：跨域 → 静态资源 → SPA 路由表 → 上传/图片/控件/素材/抓拍目录（main.js:464-487）
  ├─ SCADIA.init(server, io, settings, logger, events)（main.js:353）→ 加载工程与各子系统
  └─ 事件 'init-runtime-ok' → startScadia() → SCADIA.start() → server.listen(uiPort)（main.js:344-347, 608）
```

启动成功日志特征（排障用）：`SCADIA started!` + `WebServer is running http://<host>:<port>/`（运行实例实测）。

### 3.2 运行总线 `runtime/index.js`

- 用一个 `EventEmitter`（`runtime/events.js:47-52` 的 `create()`）把各子系统串起来，并把事件转发到 Socket.IO（`runtime.io`）。
- **事件名统一登记在 `server/runtime/events.js:7-43` 的 `IoEventTypes`**，客户端 `client/src/app/_services/hmi.service.ts:240-352` 逐条订阅同名事件——**这是前后端之间唯一的实时契约**。

### 3.3 Socket.IO 事件全表（前后端实时契约）

## §6 数据流（端到端）

### 6.1 采集（读）

```
驱动按 polling 周期轮询
  → 驱动解析出 { tagId: value }
  → runtime/devices/device.js 统一外壳
  → runtime/index.js 总线：① 更新内存值 ② 变化/死区判定 ③ 报警判定
  → ④ Socket.IO 广播 'device-values' ⑤ 需归档的写 DAQ
  → 浏览器 hmi.service 收到 → 更新画面 Tag.value → 控件重绘
```

### 6.2 操作（写）

```
操作员在画面点按钮/输入值
  → Socket.IO 写请求（hmi.service.putSignalValue）
  → runtime → device.setValue / setValues
  → 驱动打包协议帧下发 PLC/网关
  → **等设备确认后**回报结果（本项目刻意修正为"诚实写"）
```

### 6.3 报警

值变化 → `runtime/alarms` 规则判定 → 产生/更新报警记录 → `alarms-status` 推送 → 画面报警条/报警页 → Ack/Resume → 历史落 `alarms.scadiap.db`。

### 6.4 历史（DAQ）

带 `daq.enabled` 的变量按 `interval` 或变化量写入所选后端；查询走 `GET /api/daq` 或画面历史曲线控件（走 `daq-query`/`daq-result` 事件）。

### 6.5 一个点位的一生（把上面串起来）

1. 工程里建 `Device`（`type` 决定用哪个驱动）+ `Tag`（填 `address`，`daq.enabled=true`）
2. 驱动按 `polling` 读 → `{ tagId: value }`
3. 值经总线 → `device-values` 推给浏览器 → 画面数字跟着变
4. 超阈值 → 报警 → 报警条亮起 → Ack 写历史
5. 到 `interval` → 写历史库 → 曲线可查
6. 操作员改设定值 → 写回 PLC（等确认）
7. 第三方系统经 OPC UA（:4840）读同一批变量

## §7 画面运行时与组态编辑器

### 7.1 画面数据模型

```
View { id, name, type: 'svg'|'cards'|'maps',
       profile { width, height, bkcolor, align, scaleMode? },
       svgcontent: '<svg>…</svg>',        // 画面本体（纯 SVG 字符串）
       items: { <elementId>: GaugeSettings } }   // 控件表；key 必须等于 SVG 元素 id
```

### 7.2 渲染流程（`scadia-view.component.ts`）

1. 取 `view.svgcontent` 插入 `#content` 容器；
2. `loadWatch()`（`:506-560`）遍历 `view.items`：`initElementAdded` 生成控件实例 → `bindGauge` 绑定信号与鼠标事件（`gauges.component.ts:294-335`，用 `document.getElementById(ga.id)` 找元素）；
3. `applyContentDictionary()`（`:130-161`）按语言替换文本；
4. 缩放：`resolveScaleMode`（`:341-364`）按 **显式入参 → view.profile.scaleMode → layout.viewScaleMode → 有整屏底图则 `fill` → 否则 `contain`** 决策，`Utils.fitView` 施加 CSS transform。

**缩放六模式**（`_models/scale-mode.ts`）：`none`（1:1 溢出滚动）、`contain`（等比完整，可能有黑边）、`stretch`（铺满但变形）、`cover`（铺满并裁切）、`width`（按宽适配）、**`fill`（双层：整屏底图 cover 铺满 + 画布 contain 保证控件不被裁）**。
> `fill` 是"大屏不留黑边"的正解：它把画面里那张整屏底图提出来铺满容器，画布本体仍等比居中，因此既不裁控件也不留边。判定条件见 `Utils.findBackdrop`（`_helpers/utils.ts:582-598`）：存在 `x≤1, y≤1, w≥98%画布宽, h≥98%画布高` 的 `<image>`。

### 7.3 事件与动画

- 控件事件模型：`GaugeSettings.property.events[]`，元素形如 `{ type:'click', action:'onpage', actparam:'<viewId>', actoptions:{} }`——**`type`/`action` 存的是枚举"键名"而非枚举值**（判定见 `gauge-base.component.ts:49-61` 的 `Object.keys(GaugeEventType)` 与 `home.component.ts:602` 的 `action === 'onpage'`）。
- 页面跳转：`onpage` 由 `home.component.ts` 处理（`handleMouseEvent` `:597-614` → `onGoToPage`），其余动作转发给 `scadia-view.runEvents`（`:814-840`）。
- 动画/变色：`property.actions[]`（隐藏/显示/闪烁/颜色/旋转/移动/按标签移动/加载图像…，`_models/hmi.ts:332-350`）+ `property.ranges[]`（按数值区间着色）。

### 7.4 组态编辑器

- 画布是 **vendored svg-edit**（`assets/lib/svgeditor/scadia-editor.min.js`，jQuery 时代库，内部版本 `editor v2.9.12-173`），Angular 负责面板与属性对话框，两边通过全局 `window.svgEditor` 通信（`editor.component.ts:226-295` `myInit()`）。
- 工具箱三大来源：通用图元（`my-shapes.js` 39 个）、工业符号（`proc-shapes.js` 112 个 P&ID）、动画图元（`ape-shapes.js` 2 个），**加载表见 `assets/lib/svgeditor/shapes/shapes.js:11`**——磁盘上还有 3 个未被加载的死文件（`proc-general/pumps/comp-shapes.js`）。

- 详细清单（面板、工具、属性、动画连接、快捷键、缺失项）见本仓库前的编辑器核查结论与 `03_核查与风险报告.md`。
