# 开诚智枢scada 架构手册（工控 + 程序员 双视角版）

> 本手册目标：**同一个系统，两种人各自都能读到能干活的程度**——
> 现场/工控人员读到「怎么用、怎么排障、数据从哪来」；程序员读到「代码在哪、函数叫什么、数据怎么流」。
> 写法约定：每处尽量给两句——**「现场人看这里」**（说人话）与**「程序员看这里」**（给文件/函数）。
> 必须出现的术语在第 10 章有对照表；代码地图在第 0.2 章。

## 0. 一眼看懂（TL;DR）

| 问题 | 答案 |
|---|---|

| 服务端在哪 | `…\开诚智枢scada\server`（Node.js） |
| 前端在哪 | `…\开诚智枢scada\client`（Angular；构建产物 `client\dist`） |

## 1. 这套系统的定位与「血缘」

- **血统**：SCADIA 是开源 Web SCADA（MIT）。本仓库在其之上做了**本地化 + 行业增强**：
  - 中文界面与命名；煤矿/皮带/泵房等场景；
  - **校准标定模块**（calibration）；
  - **视频监控本体**（cameras）、**GB28181 国标接入**、**AI 视频分析**；
  - **OPC UA Server**（把本平台数据对外发布）；
  - **WebSocket / HTTP(WebAPI) 设备驱动**；
  - **设备→通道→变量 三层模型**（本仓库 B4 增强）；
  - **展厅(展厅)工程画面迁移工具链**（把老组态工程迁到本平台）。
- **许可**：MIT（`LICENSE`）。二次开发**保留**了原版权头，这是合规要求。
- **你的工程是「数据」，不是「代码」**：平台代码（本仓库）与工程数据（`_appdata` 下的 `*.db`）是分开的。换工程 = 换 `_appdata` 里的库文件。

## 4. 数据是怎么流的（最重要的一章）

### 4.1 采集（读）

```
驱动按 polling 周期轮询设备
   → 驱动解析出 { tagId: value }
   → device 外壳 → runtime（运行总线）
   → ① 写入内存值表  ② 变化检测(deadband)  ③ 触发报警判断
   → ④ 打包通过 Socket.IO 推给所有浏览器  ⑤ 需要归档的写入 DAQ
```

### 4.2 操作（写）

```
浏览器点按钮/输入值
   → Socket.IO 到服务端
   → runtime → device.setValue(tagId, value)（或批量 setValues）
   → 驱动把值翻译成协议帧 → 下发到 PLC/网关
   → 结果（成功/失败/被拒）回给浏览器
```
> 本仓库修的诚实语义：写入是**等设备确认**才回报成功，不再「发出去就报成功」。

### 4.3 报警

```
值变化 → 报警规则(条件/优先级) → 命中即产生报警记录
   → 推送到浏览器（画面/报警条）→ 可确认(Ack)/恢复(Resume) → 存 alarm 历史
```

### 4.4 历史（DAQ）

```
带 daq.enabled 的变量 → 按 interval 或变化量 → 写入历史库
   存储后端：SQLite（默认，_db\daq-data_*.db） / InfluxDB / QuestDB / TDengine
   查询：REST /api/daq，或画面里的历史曲线控件
```

### 4.5 视频 + AI（本仓库增强）

```
摄像机(RTSP/GB28181) → cameras 子系统
   → 预览/云台PTZ/预置点；GB28181 走 SIP 信令 :5060
   → 视数融合：视频↔变量双向（画面上叠加实时值，或变量驱动云台/录像）
   → AI 分析：结果经 :1890 进平台 → 触发工程报警/事件
```

### 4.6 举例：一个点的「前世今生」（现场 → 代码 → 现场）

> 这是全篇的**缝合处**。用「现场人」的语言起头，每步补一句「代码里」。

**场景**：1 号皮带机有个温度点，PLC 里叫 `DB1.DBW10`，希望在画面上看到它，超 60℃ 报警，并每小时存一次历史。

1. **现场人说**：这个点属于「1 号皮带」这台设备，接在 S7-1200 上。
   **代码里**：在工程里建一个 `Device`（`type=SiemensS7`），新建一个 `Tag`（`address` 填 PLC 地址，`daq.enabled=true, interval=3600`）。

2. **现场人说**：平台每隔一段时间去读它。
   **代码里**：驱动按 `polling` 周期轮询，`runtime/devices/s7/index.js` 读出 `{ tagId: value }`。

3. **现场人说**：值变了，画面上的数字要跟着变。
   **代码里**：值经 `runtime/index.js` 总线做「变化检测」，通过 Socket.IO 推 `device-values` 给浏览器；`hmi.service.ts` 更新画面 `Tag` 的 `value`。

4. **现场人说**：超过 60℃ 要报警。
   **代码里**：`runtime/alarms/index.js` 命中规则 → 产生报警记录 → 推给画面报警条、可选存 `alarms.scadiap.db`。

5. **现场人说**：每小时存一次历史，以后能查曲线。
   **代码里**：DAQ 按 `interval` 写 `_db/daq-data_*.db`（或 InfluxDB 等）；查历史走 `GET /api/daq` 或画面历史曲线控件。

6. **现场人说**：操作员在画面上改个设定值，要下到 PLC。
   **代码里**：浏览器 Socket.IO → `device.setValue(tagId, value)`（批量 `setValues`）→ S7 驱动打包写帧下发 → **等设备确认才回报成功**。

7. **现场人说**：这台设备还能被别的系统读。
   **代码里**：`runtime/opcua-server` 把变量发布到 `opc.tcp://<ip>:4840/UA/SCADA`，第三方按 OPC UA 客户端读。

> 记住这条链：**现场协议 → 驱动 → 运行库 → 画面/报警/历史/OPC UA**。任何「数据不对」的排障，都顺着这条链从两头夹。

## 5. 数据模型（记住这张「树」）

```
工程（Project）
├─ 设备（Device）            ← 一台 PLC / 网关 / 仪表
│   ├─ 通道（Channel，可选）  ← 设备下的分组（本仓库三层模型）
│   │   └─ 变量（Tag）        ← 一个点：地址、类型、单位、是否归档…
│   └─ 变量（Tag，无通道时直接挂设备）★ tagId 是全局唯一主键
├─ 画面（View）               ← 一张 HMI 画面：背景 + 一堆元件(SVG)
├─ 报警（Alarm）             ← 报警定义
├─ 配方（Recipe）            ← 批量参数
├─ 脚本（Script）            ← 画面/系统逻辑
├─ 定时任务（Scheduler）
├─ 报表（Report）
├─ 用户/权限（User）
└─ 相机/GB28181（Camera）
```

**关键约定（务必记住）**：
- **变量最小单位是 Tag**，它的身份是 **`tagId`**（一串 GUID）。历史、报警、标定**都按 tagId 存**，所以 **tagId 不能随便改**。
- 本仓库的「通道」是**变量身上的一个属性 `channelId`**，不是把变量搬进通道里——这样 tagId 不变，历史数据不受影响（详见第 6 章）。

## 6. 本仓库的重点增强（二次开发内容）

### 6.1 设备→通道→变量 三层（B4）

- 存储形态：
  - `device.channels = [ { id, name, ... } ]`（通道描述，可选）
  - `device.tags = { <tagId>: { …, channelId } }`（**变量仍是扁平的、key=tagId**）
- 好处：对历史/报警/标定/驱动**零影响**；没有通道的老工程照常跑（归入隐式「默认通道」）。
- 接口：`GET/POST/PUT/DELETE /api/devices/:id/channels`、`POST /api/devices/:id/tags/assign`。
- 前端：设备页有「通道」列、通道筛选、通道管理对话框。

### 6.2 变量定义导入/导出

- `GET /api/devices/:id/tags` 导出（只含定义字段，剔除运行值）；
- `POST /api/devices/:id/tags` 导入（只增不删，已存在默认跳过，`overwrite:true` 才覆盖且不丢当前值）。

### 6.3 WebAPI / WebSocket 驱动增强（B3/B2）

- 批量写、长轮询/ETag 条件请求、诚实写（等响应）；WebSocket 帧驱动。

### 6.4 视频（A 阶段）

- cameras 本体、GB28181 国标接入、AI 视频分析、视数融合。

### 6.5 展厅(展厅)工程画面迁移工具链（展厅）

```
展厅 .gxdoc(加密) ──用展厅自带序列化器解密──► 明文 XML
        │                                        │
        │                          server\tools\ic-to-scadia.js（转换器）
        ▼                                        ▼
   docs\展厅\decrypted\g*.xml        平台 view（svgcontent+items）
                                                 │
                                    server\tools\verify-views.js（逐元素几何校验）
```
- 外壳（顶栏+左列表+中页）为**响应式**：随分辨率自动适配、满屏无缝。

## 11. 排障速查

| 现象 | 先看 |
|---|---|
| 网页打不开 | 进程是否在、`1881` 是否监听、`_logs\scadia.log` 启动行 |
| 数据不刷新 | 设备是否 enabled/在线、驱动地址、`polling`、`_logs\scadia.log` |
| 画面空白 | 前端是否已 `ng build`、`client/dist` 是否为最新 |
| 图片不显示 | 路径是否 `/_images/...`（HTTP 走 `_images` 目录）、文件名/大小写 |
| 写值报错 | 设备是否可写、`secureEnabled`、OPC UA 是否 read-only |
| OPC UA 连不上 | `4840` 监听、证书/端点 URL `opc.tcp://<ip>:4840/UA/SCADA` |
