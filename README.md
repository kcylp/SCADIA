# SCADIA — 工业监控与八场景视频分析

本仓库保存独立 SCADIA 工程的源码、实施计划和维护文档。主要技术为 Angular、Node.js/Express、SQLite、Python 视觉服务。现场工作站使用 `http://127.0.0.1:1881`，视频代理使用 `127.0.0.1:1886`。

**当前版本可用于部署、联调和现场验收。门口实际几何标定、真实正反通行、专项识别准确性及长期稳定性尚未完成验收。MES/EMS 展示页含示例数据，不能当作生产实绩。** 本说明以可核对的代码和测试为依据，完整边界见产品说明书。

## 八场景对应关系

| ID | 本现场目标 | 来源与限制 |
|---|---|---|
| V1 | 指定门口进入 | 可见光；仅指定门口向内过线，当前实际位置未标定 |
| V2 | 蹲下 / 倒地 | 可见光姿态候选，蹲下也需记录 |
| V3 | 点烟 / 吸食 | 可见光候选与 VLM 复核，手口动作可能有混淆 |
| V4 | 戴安全帽 | 办公室反向规则：戴帽为目标，未戴帽正常 |
| V5 | 4 人及以上聚集 | 同画面人数，不排除工位坐着的人 |
| V6 | 原位连续 30 秒静止 | 连续轨迹计时，单帧不能证明时长 |
| V7 | 小火苗 / 通道 / 画质 | 打火机出现可见火苗即为目标，通道区域待标定 |
| T1 | 红外相对热源辅助 | 独立红外流；无真实测温接口，不输出真实体温 |

统一 AI 默认提供 V1–V7、T1 目标。每个目标读取自己的持久事件、事件复核和历史证据；巡视、候选、VLM结论和人工确认分开显示。视频源离线不会删除历史记录。证据不足不会被写成现场正常；分析不会执行设备控制。

## 常用入口

- `/scenes`：八场景画面与门口标定。
- `/people`：指定门口进入记录。
- `/scene-records?scene=V3`：八场景记录筛选与分页，可切换 V1–V7、T1。
- `/ai-analysis`：统一 AI 分析及管理员模型配置。
- `/mes`、`/ems`：业务展示；实际业务证据绑定需另行配置。

全局场景文件还没有逐相机 ACL；安全模式下场景状态、实时帧、事件和证据需要管理员。开放演示模式允许浏览，写入仍要求有效管理员身份。

## 运行已有现场工程

Windows PowerShell，在仓库根目录：

```powershell
.\start-scadia.ps1
```

也可双击 `启动 SCADIA.cmd`。脚本使用本机 `project`，按配置启动代理、事件桥接、可见光追踪、独立红外追踪和本地 VLM。缺少配置或权重会跳过相应服务。登录使用现场授权账号。

**GitHub 源码不包含现场 `project`、模型、Node/FFmpeg 二进制、依赖、数据库、密钥和抓拍。** 新克隆先按部署维护手册准备环境和工程备份，不能据源码仓库的缺省启动认定八场景已接通。

## 从源码构建与检查

```powershell
cd source\server
npm ci
npm run build
npm run test:lint
npm test -- --exit
cd ..\client
npm ci
npx tsc --noEmit -p src/tsconfig.app.json
npm run build -- --configuration production
cd ..\..
python -m unittest discover -s source/tools -p "test_scadia_scenes.py"
```

服务端、客户端和 Python 的检查范围不同。运行 `deploy-scenes.ps1` 前须先构建，脚本只负责本工程进程重启和 `/api/version` 就绪探测。升级前备份 `project` 和模型/依赖清单，详见部署维护手册。

## 工程结构

```text
source/client/      Angular 界面源码与构建入口
source/server/      Node.js 服务端、API、运行时、自动化测试
source/tools/       视觉追踪、状态机、VLM主管、视频代理及检查工具
docs/               当前产品说明书、使用手册、部署维护手册
docs/archive/       旧规划、评审与交接文档
project/            本机现场工程、私有配置与运行数据（不入库）
models/             本机模型权重（不入库）
runtime/            可选便携 Node / FFmpeg（不入库）
```
