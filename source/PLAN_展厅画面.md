# 展厅画面 1:1 呈现计划（展厅 展厅 → 开诚智枢scada）

> 目标：展厅工程「展厅」有几张画面，我们平台就建同样几张，**逐一 1:1 呈现**——
> 尺寸 / 布局 / 层级 / 文字 / 字体 / **全部配色** / 图片 / 变量绑定 / 动画，一个细节都不少；
> 并**接入视频（多路）**。展厅那套视频控件我们能做，而且能做得更多路。

本文件是本工作流的计划书；平台上位集成的总体计划仍在 `PLAN_集成规划.md`。

## 0. 一句话结论

展厅的画面定义（`.gxdoc`）是**私有加密的 .NET 序列化文档**，但它用的是展厅**自己的托管程序集**来读写。
因此呈现走 **A 路线：解出真实定义 → 结构级呈现**（保真最高，含坐标与配色），
而不是只能「照截图描」。B 路线（渲染比对）作为校验与兜底。

## 2. 呈现路线

### 路线 A（主）— 解出真实定义，结构级呈现 ★推荐

1. **打通解密/反序列化**：用展厅自带程序集（`FileCompressor` / 文档序列化器）在 PowerShell 里反射调用，
   把 `.gxdoc` / `VScreen.cfg` / `Graphics.dat` / `Video.DAT` / `IO.psds` 解成明文（XML/对象）。
   - 先验证性目标：**解出 1 张画面的完整元素树**（类型/坐标/尺寸/Z序/样式）。
2. **拿到权威清单**：画面 id → 名称、画布尺寸、启动画面。
3. **写转换器**（离线脚本，纯函数）：展厅 Shape → 平台 view 元素，1:1 映射（见 §3）。
4. **资源落地**：图库 PNG/JPG 拷进平台资源目录，按引用重连。
5. **生成 view JSON** 并导入平台工程（`hmi.views`）。

产物：每张画面一个 view，元素级可编辑、可绑定变量，**坐标与配色与原画面一致**。

### 路线 B（备 / 校验）— 渲染比对

- 用 `展厅设计器`/`展厅运行端` 逐屏渲染并截屏（原生 1920×1080）→ ① 作为路线 A 的**像素级验收基线**；② A 若在某控件上受阻，则该屏退化为「原图当背景 + 重建交互控件」。
- 截屏可用本机 `pyautogui` 工具完成；比对用 Python(PIL/numpy) 做像素差与 OCR 校验文字位置。

> 两条路线不互斥：**A 出结构，B 出判据**。M4 阶段用 B 做最终 1:1 判定。

